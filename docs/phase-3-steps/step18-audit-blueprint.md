## 2. Permutations, axe, screenshots
A permutation = one seed: a script of 8-14 gestures (pager next/prev/first/size, header sort, floating text filter typed through the debounce, number filter, set filter open/tick/Apply, quick search typed char by char with/without pauses, clear all, refresh, Retry after an error, select all matching), same list for A and B; per request a seeded latency (0-1 200 ms, ties) and failure draw (~8 %); release policy fifo/lifo/random/burst.
Oracle from the gestures (not the kernel): `ref(universe, intendedQuery)`. Invariants after every release and at quiescence: I1 no stale rows (displayed = prefix-consistent ref of a current query; at quiescence = ref(current) page-sliced); I2 superseded signals aborted, no stale answer applied (server log vs gate diagnostics), nothing after destroy; I3 aria-busy iff a current request pending, stale styling while old rows kept, one settled announcement per result-changing user action, none with a superseded count, silent when the count is unknown; I4 footer text, aria-disabled and "Select all N" consistent; "all" tied to the current query; I5 the search box never rewritten by an answer; focus stays on the control used; I6 one request per typing pause with trimmed quick; a page change in A asks nothing; pages held ≤ 2 in B; I7 A and B show the same ids at quiescence.
