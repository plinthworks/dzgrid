# Step 12 blueprint: `/filters` part 1, the floating row (architect, 2026-10-19)

Decisions on top: `step12-decisions.md` (they win). Byte figures are estimates.

## 0. Findings that shape the design
1. `grid.ts` is at its 250-line cap (structure.test.ts): base changes go to features.ts / part.ts, net zero lines in grid.ts.
2. Without `spans()`, extra header rows sit side by side: `:where(.dzg-header){flex-direction:column}` is only in SPANS_CSS. Move it to the base LAYOUT_CSS, drop it from SPANS_CSS (jsdom cannot see it: browser check).
3. Keys: `INTENT_OWNERS.enter = ['cell']`, `leave = ['cell-widget']`; conformance `escape-filter-input` and `filter-input-enter` say intent null; Enter on a floating cell reads as `sort`, ignored at level > 0; F2 yields nothing. So Enter/F2 to enter and Escape to leave are handled by the feature on the cell. No core change, no conformance change.
4. HeaderRenderer drops a cell leaving the column window with no callback: sweep in `afterRows()` as slots does.
5. `unslotted()` in part.ts flags every non-cell part as missing-feature detail `slots`: make it a slot→feature map.
6. Kernel quirk (not fixed here): `setQuery` compares raw filters, so an inactive stored filter counts as filtered (with keepOnFilter:false it clears the selection). Built-in floating parts never store an inactive filter (empty box → `filter.column null`); the contract tells custom parts to send null when `kind.active` is false.
7. Client: `modelUpdated` before `filterChanged`; server: `filterChanged` first. grid.ts does not paint on `filterChanged`: the feature calls `g.schedule()`.
8. The grid carries `aria-readonly="true"`: cells with an input get `aria-readonly="false"` (axe + by ear).
9. Bundles require every key (`checkMessages`), 2 kB gz ceiling per bundle → separate filter bundles (owner O1).
10. `ColumnDef.filter` is `false | {kind?}`: `floating` and `debounceMs` are type-only additions in core (columns/defs.ts, columns/parts.ts PartColumn).

## 1. API
```ts
// @dzgrid/dom/filters (src/filters.ts -> src/filters/index.ts); exports "./filters"
export function filters(o?: { floating?: boolean; debounceMs?: number }): GridFeature;
// GridFeature: new optional readonly parts?: Readonly<Record<string, SlotPart>>
// filters() = { id: 'filters', parts: { 'floating.text', 'floating.number', floating: summaryPart }, setup }
```
Column: `filter?: false | { kind?: string; floating?: boolean; debounceMs?: number }`; floating = column value, else grid option (`filter.floating:false` hides one column). `ops`, `values` at steps 13, 15.
Row presence (owner O3): fixed at creation — the row exists if `o.floating === true` or a column has `filter.floating === true` at setup (check hidden columns are counted). A column without a floating filter gets an empty `.dzg-hextra` cell (pairing rule).
Parts registry (`GridFeature.parts`): base `featureParts(features)` — first feature wins per name, `settings.parts` beat features, memoised on the identity of `settings.parts`; `GridContext.parts()`; consumers switch to it: viewport.ts `resolveParts`, slots/resolve.ts, slots/index.ts overlay lookup. Live: a new registry re-resolves floating cells. No `part-shadowed` (step 22). `unslotted` map `{header, overlay, tooltip: 'slots', floating: 'filters', filter: 'filters', footer: 'pagination'}`, told when `initial.features` lacks the id, once at creation. A column with `filter.floating` or an explicit `filter.kind` and no `filters()` → `missing-feature` detail `filters` at `columns[i].filter` (owner: yes, in the base).
Resolution per column: skip if `filter === false` or not shown; `kind = filterKindOf(col)`; explicit unknown `filter.kind` → `invalid-filter` detail `unknown kind` at `columns.<id>.filter.kind`, once per registry, cell empty; implicit custom type silent and empty; a custom kind without `test` under client ops → empty, no problem. Name: `partNameFor('floating', col, names)` → `floating.<kind>`, else bare `floating` (the summary, a host's `floating` replaces it). `floating.text` = kind text, `floating.number` = number; day, instant, boolean, set, custom without their own part → summary.
Contract (type only in part.ts; SlotContext gains `floating`, WiredSlot follows):
```ts
floating: PartBase & {
  readonly column: ResolvedColumn<unknown>;
  readonly kind: string;
  readonly state: Json | null;     // built-ins: the stored ColumnFilter; custom: its .state; null = none
  readonly where: Placement;       // rows.ops.filter
  readonly debounceMs: number;     // column > filters() > 150 client / 300 server
  set(next: Json | null, o?: { commit?: 'now' | 'debounced' }): void;   // default debounced
}
```
`set(null)` removes; custom kinds wrapped `{type:'custom', kind, state}`. No `openPopup` / `values` / `close` at step 12 (13, 15). `PartHandle.focus()` returns true if it took the focus. Mounted rules (functions not compared, throw → destroyed and reported, not retried until the context changes).
Summary part (bare `floating`): only when a filter exists: read-only `<span>` "Filter active" (no column, owner O4) + Clear button (`aria-label` `filter.clear {column}`) → `set(null, {commit:'now'})`. Inactive: empty cell. Step 13 turns it into the popup button.
Inline box scope (owner O3): `floating.text` edits null or `{type:'text', op:'contains'}` (keeps caseSensitive); `floating.number` edits null or `{type:'number', op:'equals'}`; any other state (another op, between, blank, combined) shows summary + Clear. `>5` syntax: Phase 5.
Clear-all (step 11 carry-over): slots `clearFilters` = `send({type:'query.set', query: makeQuery({sort: g.kernel.query.sort})})` — one setQuery, one server request. Test: a source fake sees one request.

## 2. Behaviour
Box: `type="text"`, `data-dzg-owner="filter-input"`, autocomplete off, spellcheck false, `aria-label` `filter.inputLabel {column}`, no placeholder. Number: `inputmode="decimal"`, never type=number. Commit: text empty → null; text → `{type:'text', op:'contains', value}` as typed (no trim); number via core `readNumber(text, ctx)` (fr `1,5`, ar `١٫٥` and Latin, `12%`) → `{type:'number', op:'equals', value}`.
Debounce: owned by the feature, one pending edit per column (replaced by the next; `commit:'now'` flushes). 150 ms client, 300 server, overridden by `filter.debounceMs` then `filters({debounceMs})`; non-finite or < 0 → default. `g.win.setTimeout`, at once without a window. Flush on Enter, Escape, focusout of the cell, sweep. Grid destroy clears timers and drops pending edits without dispatching. A refused dispatch → `problems` event, source user. Dispatch source user.
Invalid numbers: no dispatch, the previous filter stays; judged at commit (not per keystroke: `-5` does not flash); any input clears `aria-invalid`; entering invalid: `aria-invalid="true"` + one `announce(filter.invalid {column})`; non-colour cue (2 px outline). IME: ignore `input` with isComposing; commit at compositionend.
Echo on update: the part keeps the canonical form it last sent; equal state → text untouched (`1,50` not rewritten while focused); otherwise external (host filter.set, Clear, overlay clear-all) → rewrite (numbers `formattersFor(ctx).number({useGrouping:false})`); uncommitted typed text is left alone.
Server: only a longer debounce; empty or invalid → no request. Test with sourceRows: one request per pause, none for an empty edit on an unfiltered column, an exclude-mode all-selection survives.
Announcement (feature): on `filterChanged` source user: not loading → announce now; loading → on the next non-loading `modelUpdated`; `fetchFailed` clears. `announce.filtered {rows: announce.rows{n}}`, unknown count → `announce.filteredOpen`. Also `g.schedule()` on filterChanged.
Keys and focus: floating cells at level 1 of the roving order (Down 0→1→first row; Up from first row → 1 → 0 → group bands); reuse `moveFocus` (extras, bands); test with spans groups and box=1. Enter/F2 on the cell (target the cell, no modifier): preventDefault, stopPropagation, `handle.focus()` (input focused, content selected). Inside the input owner `filter-input`: arrows, Home, End, Ctrl+A, Space stay in the input; Enter flushes and stays; Escape preventDefault + stopPropagation, flush, `cell.focus()` (filter kept). Cell-level, so custom parts get them. Tab: controls in floating cells `tabindex=-1` (one header tab stop); `focus()` sets the cell's controls to 0, focusout leaving the cell resets to -1; test: one tabbable in the header. Pointer: no sort, no tooltip, no grip on `.dzg-hextra`. focusin maps an input to `{kind:'header', column, level}`; `keep` keeps the focused column mounted.
a11y: header row counted in aria-rowcount/rowindex, `role=gridcell` cells, `aria-readonly="false"` on cells with an input, box name `filter.inputLabel`, no aria-describedby. The header part (step 11) draws level 0 only.
RTL: inputs `unicode-bidi: plaintext`, `text-align:start` (fallback `dir=auto`); logical properties only; locale numerals via ctx.numerals.
Lifecycle: `Map<cell, state>`; mount/update per paint, context recomputed only when inputs changed (state identity, column, where, ctx, dir, messages, registry, debounceMs); afterRows sweeps disconnected cells (flush, destroy); destroy clears all (mounts = destroys). Move `slots/mounted.ts` to `src/mounted.ts`, shared; amend the structure test.
