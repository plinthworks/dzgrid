# Step 14 blueprint, second pass: date filters on tzslot 2.2.0 (architect, 2026-10-19)

Supersedes the controls of `step14-dates-blueprint.md` (its ops, half-open rules, L1, server draft, echo and keys stay). Decisions in `step14-decisions.md` win. tzslot (`~/Dev/tzslot`, the owner's) is allowed by CLEANROOM.

## 0. Findings
1. tzslot 2.2.0 is on npm; `@tzslot/dom` depends on `@tzslot/core ^2.2.0`; `sideEffects:false`. The Temporal polyfill (`temporal-polyfill/full`) is a static import in `@tzslot/core/src/temporal.ts`, bundled even where Temporal is native (T3).
2. tzslot's panel goes to `document.body` by default; our popup is top layer (`popover="manual"`, popup.ts:73) so the panel would open under it. `createDateField`, `createDateTimeField`, `createRangeField` accept `container`: a node inside our popup. The panel is `position:fixed`; `.dzg-popup` has no transform/contain (styles.ts:34-35).
3. Palettes identical: dzgrid.scss:19-29 = tzslot.css:34-43 (nine `--tz-*` tokens). Missing: the panel surface (tzslot structural CSS uses Canvas/CanvasText, styles.ts:296-297).
4. tzslot has the shortcuts: `presetRange` (core/src/presets.ts) — today, yesterday, last7Days (includes today), last30Days, thisMonth, lastMonth; range field `preset` + `today`, `onChange(value, { preset })`; passing `preset` back is resolved again against today (range-field.ts:2538-2560).
5. tzslot defaults `timeZone`/`today` to the machine's (`Temporal.Now`): always pass both; test under `TZ=Pacific/Auckland`.
6. DST: a skipped time is moved later with a visible notice (`settle()`, datetime-field.ts:571-580); a repeated time takes the earlier reading and shows two reading buttons (:581-593); both return an Instant. So `filter.timeSkipped`, `filter.timeAmbiguous`, `filter.invalidDate` disappear (reverses the first plan's "refuse a skipped time": tzslot is the control).
7. Base headroom 48 B: nothing new in the base; the midnight timer lives in `filters`.

## 2. Mapping onto DzGrid's model
DzGrid holds the draft in its own types (Day string, `at` UTC Z); tzslot is only the view; `update(...)` never calls `onChange` (except range `preset`, muted).
| Column / op | widget (zone) | model |
|---|---|---|
| day equals, notEqual, lt, lte, gt, gte | createDateField | `value: Day` = `parseDay(plainDate.toString())` |
| day between (inclusive) | createRangeField (`showTime:false`, `timeZone:'UTC'`) | `value` = start date, `valueTo` = end date − 1 day |
| day relative (under between) | same + `preset` | `{op:'relative', range}` |
| instant onDay | createDateField | `day` |
| instant betweenDays | createRangeField (`showTime:false`, grid zone) | `day`, `dayTo` |
| instant relative (under betweenDays) | same + `preset` | `{op:'relative', range}` |
| instant between `[at, atTo)` | createRangeField (`showTime:true`, grid zone, no presets) | `at`, `atTo` |
| instant before, after | createDateTimeField (grid zone) | `at` |
Day columns: `'UTC'` midnights only as carriers; `messages.periodSummary: ({length}) => length` to hide "· UTC" (T6). `at` = `instant.toString({ fractionalSecondDigits: 3 })`, accepted when length 24; no `Date` in adapters; stored `at` read with core `readInstant` then `Temporal.Instant.fromEpochMilliseconds`. Editable only if: day parses within 0001-9999; `at` a whole minute within 1900-9999; op in `column.filter.ops`; relative name in our six — else summary + Clear. Range incomplete → inactive (L1). Settings always: `timeZone: ctx.timeZone`, `today: PlainDate.from(instantToDayIn(clock(), ctx.timeZone))`, `locale: intlTag(ctx)`, `messages`, `ariaLabel` + `title` (`filter.date`, `filter.dateTime`, `filter.period`), `placeholder: ''`, `readingStyle: 'named'` ("02 — été / hiver"), min/max (day 0001-01-01..9999-12-31; instant 1900-01-01..9999-12-31), `buttons: []`, range `clearable: false`, `confirm: false`, `injectStyles: false`, `container` = the field's wrapper. Single date and range commit now; the typed datetime field commits debounced (server still waits for Apply). `muted = true` around `update`; a preset click → `{op:'relative', range}`, a manual edit (`preset:null`) → plain between/betweenDays.
Locale: `intlTag(ctx)` from core/internal = e.g. `ar-SA-u-ca-gregory-nu-latn` (locale digits when `ctx.numerals === 'locale'`): Gregorian forced, the grid's digits. Test: ar-SA Gregorian, ar-DZ Latin, ar-EG + `numerals:'locale'` Arabic-Indic. `messages`: tzslot's `EN`/`FR`/`AR` by language subtag, else EN; `filters({ dateMessages })` override. Shortcut labels from tzslot's catalogues (owner reads the AR ones). Direction: popup `dir`; tzslot `carryTheme` copies it to the panel; dir change closes the popup (O9).
Agreement of the two engines: both read the same tz data (core via Intl `offsetAt`, zone-day.ts:88; Temporal native or polyfill via Intl). Cases (Paris): gap 2026-03-29 02:30 → both 01:30Z; repeated 2026-10-25 02:30 → both first 00:30Z (second via tzslot's button); day starts (incl. São Paulo 2018-11-04, Havana); instant→day; Apia 2011-12-30 empty. Test `packages/dom/test/tzslot-agreement.test.ts`: 13 zones (wire-property set + Lord Howe, Apia, Havana, São Paulo), 2010-2030, every transition day, every wall minute: classification, instants, `offsetAt` vs `offsetNanoseconds/1e6`, day starts and instant→day (sampled), `relativeDays` vs `presetRange` for the six names over a year of `today` plus month/leap/year edges; both TZ. If they ever differ: DzGrid's core decides rows and wire; tzslot what it shows; the sweep fails first.
Nesting: `.dzg-fpop` → per field `div.dzg-fdate` = [label][tzslot host][panel container]; the panel stays inside the popup (top layer, `data-dzg-owner="popup"`, dir, theme). Escape: tzslot closes its panel from a `document` listener (panel.ts:261-268) without stopping it; our popup sees it first → a capture `keydown` on the form host: if a `.tz-field__panel` is open, `field.closePanel()`, preventDefault, stopPropagation; the second Escape closes the popup (T8 would remove this). Enter: `form()`'s Enter stands down when the target is inside `.tz-field__panel`. Tab: our trap at the popup's first/last only; tzslot traps inside its panel; invariant: the date trigger is never first or last. Pointer: tzslot closes its panel on outside pointer down; our popup stays (O7). Closing the popup with a panel open: `body.destroy()` destroys each widget; test: no `.tz-field__panel` left. tzslot positions itself; browser test in a transformed card and a dialog. CSS (`filters/styles.ts`): `.dzg-fdate{display:grid;gap:2px}`, `.dzg-fpop .tz-field,.dzg-fpop .tz-field__trigger{inline-size:100%;min-inline-size:0}`.

## 3. Relative shortcuts (core)
Six, tzslot's `PresetName` verbatim: `today`, `yesterday`, `last7Days`, `last30Days`, `thisMonth`, `lastMonth` (no thisWeek, no sub-day). Semantics = `presetRange` (last7Days = today−6..today; thisMonth = whole month; inclusive days).
Model (filter/model.ts): `RelativeRange` union and `RELATIVE_RANGES` set; day `{ type:'day'; op: NumOp | 'relative'; value?; valueTo?; range? }`; instant `{ type:'instant'; op: InstantOp | 'relative'; …; range? }`; `DAY_OPS` = NUM_OPS + relative; `relative` added to INSTANT_OPS.
New `packages/core/src/value/relative.ts`: `relativeDays(range, today: Day): {from: Day; to: Day} | null` (Day arithmetic only) and `dayAt(now, zone): {day: Day; until: number} | null` = `instantToDayIn(now, zone)` + `zoneDayBounds(day, zone).to`; exported from `@dzgrid/core`. Day columns: `dayTest` resolves to inclusive days and reuses `rangeTest`. Instants: `resolveInstantRange(f, zone, path, now?)` relative = betweenDays on the resolved days `[zoneDayBounds(from).from, zoneDayBounds(to).to)` (last 7 days across 2026-10-25 Paris = 169 h; today 23 h / 25 h on change days). "Today" = the grid's zone for both kinds (a Day has no zone; the default zone is UTC — say so). Unknown range → `invalid-filter` at `.range`; no clock → `invalid-filter` detail `no clock`.
Clock: the core stays Date-free (K.2): `ColumnEnv.now?: number`; `ClientOptions` and the source env `now?: () => number`; `WireEnv.now?: number` (reserved wire.ts:11). DOM settings `clock?: () => number` (default Date.now) passed to clientRows/source.create (dom/src/grid.ts:91-95); tests inject a fake one. Client `inputs()` (client.ts:233) gains `day` ('' unless the filter key contains "relative", then `dayAt(now, zone).day`, memoised until `until`); `same()` compares it. `tick()` on the model (client: re-run when the day changed, notify as a query change; server: `wired = null` then `rekey()` → a new epoch, one request, none when nothing relative), forwarded by `kernel.tick()`. Timer in the filters feature: re-armed on afterRows/query change, `setTimeout(until − now + 50)` (cap 2^31−1) only while a relative filter is in force, plus `visibilitychange`. A host without `filters()` calls `kernel.tick()` (documented).
Wire (closed op set): day `{type:'day', op:'between', value, valueTo, relative:'last7Days', zone}`; instant `{type:'instant', op:'betweenDays', day, dayTo, resolved:{from,to}, zone, relative}` (`resolved` unchanged, the only field the server reads). The epoch key changes each midnight (key = wire form) and with the zone.
Conformance (`case.schema.json` optional `input.now` ISO UTC; harness env and wire suite pass it): filter-day relative-today, -yesterday-year-start, -last7Days-month-boundary, -thisMonth-leap-february, -lastMonth-january, -last30Days; filter-instant relative-today-paris-spring-23h, -today-paris-fall-25h, -last7Days-across-fall-back, -yesterday-sao-paulo-no-midnight, -yesterday-apia-skipped-empty, -today-at-algiers-midnight (23:59:59.999 and 00:00:00.000), -no-clock (problem), -unknown-range (problem); wire day-relative-last7Days, instant-relative-today-paris, relative-no-now-dropped, relative-unknown-range, relative-last30Days-wire-key. Unit: relative.test.ts, client-clock.test.ts, source-rows-clock.test.ts (midnight rollover with a stepping clock: re-filter once, server one request, none at 23:59:59, none without a relative filter via `diagnostics.filterRuns`, zone change, clock backwards).
Display: the range field gets `preset` + `today` + `value`; preset button `aria-pressed`; presets only in whole-day range forms (day between, instant betweenDays); the moments `between` has `showPresets:false`. Summary and header name stay generic (no new keys).

## 6. Lead decisions and tzslot requests
Lead: split eager/lazy with the adapters as their own budget line; K.8 = initial load, lazy kits beside it (revisit step 18); midnight timer in the filters feature, `kernel.tick()` otherwise; `filters({ loadDates })` documented advanced; `clock` setting and core `now` plumbing; wire keeps the closed op set plus `relative` and `zone`; relative "today" on a Day column uses the grid's zone; `readingStyle:'named'`; thisWeek and sub-day shortcuts Phase 5.
tzslot 2.2.0 requests (owner's library; nothing blocks, each has a workaround to remove when fixed):
- T1 (a11y, first): `createDateField` (date-field.ts:166) and `createDateTimeField` button mode (:676) set `aria-label` to the subject only — the chosen date is not in the trigger's name (`createRangeField` does "subject, value", range-field.ts:2110-2112). Workaround: a MutationObserver appending the visible text.
- T8: the panel's Escape is a `document` listener that neither stops nor prevents the event, so a host dialog around it also closes. Register with `capture: true` and `stopPropagation()` when it closes a panel.
- T3 (~23 kB): the polyfill is imported statically even where Temporal is native; a native-only entry or a lazy polyfill.
- T2: a `nonce` option for injected styles.
- T6: the range summary always prints the zone ("5d · UTC"); a `showZone` setting.
- T4: `formatWith` writes Latin digits only, while the read-only field uses Intl (disagree with `numerals:'locale'` in Arabic).
- T5 (note): widgets default `timeZone`/`today` to the machine's; we always pass both.
