# Step 21 blueprint: selection rules, global context, header parts with the column filter (architect, 2026-10-20)

Decisions on top: `step21-decisions.md` (they win). Owner clarification: the main deliverable of part C is the CAPABILITY for developers to build their own header component that drives the column filter (plain DOM and later Angular); a built-in header box is an optional extra (not in this step unless cheap).

## A. Selection rules
Setting (live): `settings.selection.canSelect?: (row: RowNode<T>, selection: SelectionState, context: unknown) => boolean | string` — true allows; false refuses; a string refuses and is the spoken reason (host-translated). `selection` = the selection the row would join (adding: kept + rows already accepted in the same action; replacing — plain click, non-additive Shift range: empty). Never asked for a row already selected (unticking always allowed, Q4). Pure and fast.
Core seam: `kernel[GATE]((prev, next, cmd) => { state, refused: RowKey[], reason?, skip?(key) })` set through `@dzgrid/core/internal` (like OWNER, kernel.ts:172); `setSelection` and `selectQuery` pass `(selection, next)` through the gate (toggle, only, range, allDisplayed, set, clear, all, allFiltered); added keys asked in screen order against a running base `prev ∩ next`; refused keys dropped; nothing changed → no `selectionChanged`; else `selectionChanged` then new `selectionRefused { source, rows, reason | null }`; the anchor moves only for an accepted row.
New pure entry `@dzgrid/core/rules`: `vetSelection(rule, ctx, rows)` (running add, exclude refusal, unknown-row refusal, reasons).
DOM feature `rules()` (`@dzgrid/dom/rules`): sets the gate (reads `settings.selection.canSelect` and `settings.context` live), paints the disabled look, announces refusals; `canSelect` without `rules()` → `missing-feature` (settings.selection.canSelect, detail rules).
Exclude mode and unloaded rows: exclude (`selection.all` tied, `allFiltered`, host exclude set) refused under a rule (`rule-needs-rows`, spoken); `allDisplayed` stays an include set of accepted rows (client, fetched set, browser page); host include `selection.set` vetted (kept keys not re-asked; unknown-row keys refused); a live rule change does not re-vet existing selection (documented); footer `canSelectAll` false under a rule; the box and Ctrl+A act on the shown rows (server pages too: Q1); `gate.skip(key)` counts refused rows as ticked for headerState `all` (cached per selection and displayed).

## B. Global context
`settings.context?: unknown`, live (`UPDATE_POLICY.context = 'live'`). Seen by every part (`PartBase.context`: cell, header, overlay, tooltip, floating, filter, footer), `canSelect(row, selection, context)`, `csvExport({ canExport(request, context) })` read at run time, host DOM callbacks (tooltip text…). Parts: `mounted()` compares values with Object.is (mounted.ts:56) → one update on a new identity; the cell fast path: bump `partRev` in `applyUpdate` when context identity changes, then `g.schedule()`; in-place mutation not seen ("pass a new object"). `context` (host) vs `ctx` (locale) both in PartBase: documented. Angular: `@Input() context` → `update({context})`. Not now: filter kinds' test/wire and value getters (core model invalidation, ~+300 B; Q3).

## C. Header parts driving the column filter
`SlotContext['header']` gains `filter: HeaderFilter | null` (null without `filters()`, `filter: false`, or an unknown kind). `HeaderFilter = Pick<SlotContext['floating'], 'kind' | 'state' | 'where' | 'debounceMs' | 'set'>`: the same pending edit as the floating box and the popup (one per column, last write wins). No canOpen/openFilter in v1 (the header has the filter button). Base/filters decoupling: a type-only `GridContext.filter: { edits(col, who: object): HeaderFilter | null; flush(column): void } | null` assigned by the filters feature in setup; slots reads `g.filter?.edits(col, labelHost)` in `drivers.header` (slots/index.ts:48). Echo while focused is the part's duty (as the floating box).
Keyboard (reuse floating.ts:62-88, extracted into `@dzgrid/dom/internal`): one tab stop (controls tabIndex -1 unless focus inside); F2 on the header cell enters (`Mounted.focus()` true, preventDefault, stopPropagation); Enter enters if the part's focus() returns true, else sorts as today; Escape inside → flush, focus back on the cell, stopPropagation (IME: only ends the composition); Enter inside → flush; focusout leaving the cell → flush, tabs back to -1; header-click already ignores interactive descendants (header-click.ts:26-27); an input is owner `editor` (owner.ts:25). The input's accessible name is the part's duty (`c.label`); the columnheader keeps its aria-label. The floating row is already optional.

## Behaviour and a11y
Refusal leaves the selection as is (accepted rows still change); spoken: one row "Row not selectable" or the host's reason; partial "6 rows selected, 2 not selectable"; the "N rows selected" sentence not said when nothing changed; a repeated refusal is heard again (forced announce: clear then set; verify the live-region API); events selectionChanged (if any) then selectionRefused, one combined sentence.
Disabled look: `.dzg-check[data-dzg-refused]` from `rules()` afterRows (no base code), muted box, cursor not-allowed, forced colours, contrast pair; NO aria-disabled on the row (it would read the whole row as unavailable); aria-selected stays the truth; a non-visual cue before trying: Q2. Cost: the rule asked for rendered unselected rows only when the selection, rule or context changed (Map<RowKey, boolean>, ~60 calls per change, 0 on scroll); the gate asks only added keys.
