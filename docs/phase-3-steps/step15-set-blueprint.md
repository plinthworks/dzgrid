## 2. Behaviour
Shell: reuse `form(make)` (Clear, Apply, server draft, live client apply, echo, summary for uneditable). `edits(s)`: null, or a `set` with exactly one of include/exclude (string arrays) and a valid `blanks`; combined or other → summary + Clear.
Layout in `.dzg-fpop`: labelled search input (text, `dir=auto`, no placeholder, autocomplete off); `<p role=status aria-live=polite>` with `count(n)` or `truncated(n)` (text set before attach: first fill not announced — verify by ear); native checkbox select-all (`all`, or `allShown` while searching; checked/unchecked/indeterminate); fixed-height `role=listbox` (`aria-multiselectable`, named `filter.popupLabel`, `aria-busy` while loading, about 10 rows); the footer. Loading/empty/error text inside the list box: no reposition jump.
Rows: [blanks entry] + values. Blanks shown only when `blanks !== 0` (no empty option) or ticked; a server's null shows it without a count; hidden during a search; select-all (shown) never touches blanks; without a search select-all includes blanks. Row = [box][label][count]; counts in locale digits, hidden when every count is null. Labels and order from the core (codec format, collator, Arabic order). Labels `dir=auto`, `unicode-bidi:plaintext`; count an isolated span at the inline end; box at the inline start; ellipsis with `title`; box drawn in CSS (shape, forced-colors OK).
Windowing (always, one path): fixed row height, an `aria-hidden` spacer, options `position:absolute` with 6 rows overscan (~25 nodes), `first = floor(scrollTop/h)`; nothing reusable from the base (grid-bound helpers); row height `1.75rem` (≥ 24 px), measured from the first row, again on locale/font change, checked at 200 % zoom; `aria-posinset`/`aria-setsize` on every option; the focused option retained, never recycled. Trade-off: full render ~8 000 nodes (20–50 ms desktop, 150 ms+ phone per open and client keystroke) vs ~75 nodes < 2 ms, ~600 B lazy. Screen readers in browse mode see rendered options only (same known limit as the grid, a11y §2 step 6d). Cut if the lazy chunk passes 3 800: full render with `content-visibility:auto` (~500 B smaller).
Listbox, not checkboxes: `role=option` with `aria-selected`, roving tabindex on real focus (better on TalkBack/iOS, matches the grid); name `filter.set.option {label, rows}` (label only when count null); one tab stop (active option tabindex 0; starts on the first selected, else the first). Tab order: search, select-all, listbox, Clear, Apply (the popup's trap counts tabindex ≥ 0).
Keys (stopPropagation on handled keys, so the shell's Enter-applies never sees Enter on an option): ArrowUp/Down (no wrap), Home/End and Ctrl+Home/End, PageUp/Down by visible rows − 1, Space and Enter toggle, type-ahead 500 ms with `localeCompare(…, {sensitivity:'base'})` in the grid's locale, click toggles and focuses; in the search ArrowDown → list, Enter = the shell's commit, Escape closes. Ctrl+A and Shift ranges: Phase 5. No RTL mirroring (vertical). If the active option disappears, focus moves to the nearest remaining one (never body).
Draft (pure `set/draft.ts`): `{mode, vals: Set<string>, blanks: boolean}`; ticked(v) = has(v) in include, !has(v) in exclude. Output include `{type:'set', include:[sorted by code unit], blanks:'include'?}`, exclude `{exclude, blanks:'exclude'?}`; `blanks` written only when not the default (include: excluded; exclude: included). Null only for exclude with an empty list and blanks ticked ("All": no filter); ticks call `changed(false, true)`. Untick everything → `include: []` (a valid filter keeping nothing; L1 does not apply; owner Q1). Mode flip only on a complete list (not truncated, no search, handle available): strictly more than half ticked → exclude, fewer than half → include; never on a tie; never during a search or on a truncated list. Select all / unselect all (shown) act on shown values only.
Client vs server: client live, ticks coalesced at `debounceMs` (150 ms; deviation from step 13's "at once": Space held and select-all give one dispatch and one announcement); Apply, Enter, Escape, close flush. Server: draft until Apply/Enter, one request; close drops. The list renders from the local draft, never `c.state`; echo rewrites a clean draft only.
Loading: client handle synchronous, search at once. Server: `handle.search()` after `c.debounceMs` (300 ms), not during IME composition (at compositionend); sent to the server (it owns the list and the cap). Loading with no result: `grid.loading` in the list, aria-busy; loading with a stale result: keep the old list dimmed, aria-busy; error: `role=alert` `filter.set.failed` + Retry (`grid.retry` → `handle.refresh()`), stale list kept, Retry moves focus to the search first. Truncated: status shows `truncated(n)`. `available:false`: fall back to `column.def.enumOptions` as `{value, label, count:null}` with a local label search; a non-enum column shows `count(0)`. Handle created on mount, closed in `Body.destroy` (a host's own handle on the same column is closed by the popup: documented).
Floating row: the summary button opens the popup; text `summarySelected {n}` in include mode (if accepted), else "Filter active".
Direction/locale/zone: the handle follows them; `texts()` rewrites static labels and aria-labels only when they differ; dir change closes (O9); logical properties.
Announcements: `announce.filtered {rows}` once per applied filter (after the answer on a server); `count(n)` after a search settles; no per-tick announcement (aria-selected is read by the screen reader; add one only if VoiceOver stays silent).

## 3. Sizes
The set filter is a lazy chunk: a thin eager proxy (loading `grid.loading`, failure alert with Retry). Eager: proxy Body, `loadSet`, registration, a shared loading/failure/Retry helper extracted from `dates()` into `filters/lazy.ts` (net neutral for dates, ~200 B saved for set), context `values`, keys array, optional summary text. Lazy: draft, windowed list, keys, search and status, select-all and blanks, enum fallback, the chunk's own CSS injected on load. Move `el`, `tx`, `labelled` into a leaf `filters/dom.ts` (re-exported by forms.ts) so lazy files don't inline forms.
Estimates: filters eager ~+760 → ask 9 300 (cuts: summarySelected −150, loadSet −30); new line "filters: set (lazy)" ~3 650 → ask 3 800 (external core, core/internal; the entry's external gains `./set/*`); bundles +230 / +280 / +420 → ask en 850 / fr 980 / ar 1 200; theme ~+145 → ask 1 800; core, dom, popup, date adapters 0.
Audit profile (sum of entries, upper bound): core 26 740 + server 5 551 + dom 18 722 + popup 1 428 + filters 8 473 + fr 636 + fr-filters 667 + theme 1 644 = 63 861 B; +csv ~65.5 kB; +spans ~73.4 kB (K.8 85 000). Step 15 initial +1.2 kB (~65.0 kB); lazy set chunk ~3.65 kB on first use. Outlook: step 16 +0.7 kB; 17 pagination +2.8 kB + 0.3 kB keys; 19 export +1.4 and +1.6 kB; 20 +0.9 kB → ~72.7 kB without spans, ~80.6 kB with spans (~4.4 kB under 85 000). ## 5. Lead decisions
Always windowed; roving focus on a listbox; ticks coalesced at the pause on the client; server search sent to the server after the pause, client search narrows in the core; blanks hidden at count 0 (unless ticked) and during a search; exclude only on a complete unsearched list; Enter in the search applies and closes, Enter on an option toggles; no Ctrl+A / Shift ranges / per-tick announcement before the by-ear test; required keys for every filters() adopter. Risks: by-ear behaviour (owner §11); a host's own handle on the same column is closed by the popup; enum-column tests change.
