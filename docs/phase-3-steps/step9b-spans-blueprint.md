# Step 9b blueprint: cell spans — rowspan and colspan like an HTML table (architect, 2026-10-18)

Owner decision (2026-10-18, high priority): all four kinds in Phase 3, right after step 9: identical values merged, spans decided by the data, grouped headers, full-width rows. Owner answers to the questions below are recorded in `step9b-decisions.md` once given.

Three things cannot be checked on paper: spike S12 comes first (G): tall cells stacked against pinned segments; `position: sticky` inside `overflow: clip`; what Chrome's accessibility tree does with `aria-colspan` / `aria-rowspan`.

## A. Model
Pure core in a new optional entry `@dzgrid/core/spans`. One function builds a `SpanMap` from the displayed rows, the visible columns in order (start, centre, end), the column rules and the row rule. Memoised on (displayed version, columns.version, rules, ctx). Computed on the displayed order: it follows sort, filter and page; it never depends on the window or the scroll. Positions are display indices and visible-column indices; identity (RowKey, column id) stays in focus and selection.
```ts
interface SpanCell { row: number; col: number; rows: number; cols: number }   // origin and extent
interface SpanMap {
  version: number;
  none: boolean;                              // no rule anywhere: today's fast path
  ownerAt(row, col): SpanCell | null;         // null = plain 1x1 cell
  coveringAbove(firstRow): SpanCell[];        // origins above firstRow that reach it (≤ 1 per column)
  inRow(row, colFirst, colLast): SpanCell[];  // spans in a row intersecting a column window
  fullWidth(row): boolean;
  problems: Problem[];
}
```
Built once per order change, O(log n) queries; sparse storage (Uint32Array run starts for merges, per-row sparse colspans); a deterministic full pass.
Kinds:
1. Identical values: `ColumnDef.merge?: true | ((a: SpanCtx, b: SpanCtx) => boolean) | { same?; within?: readonly string[] }`. `true` compares the stable export text (ColumnCache.exports), not collator ranks (which would merge e and é). Consecutive equal rows form one run; run index per (order, column) O(n), ≤ 25 ms for 1M rows. Blanks never merge (O4). `within: ['region']` cuts a run where the listed columns break.
2. Data spans: `ColumnDef.rowSpan?` / `colSpan?: (ctx: SpanCtx<T>) => number`; `SpanCtx = { row, value, key, index, column, prev, next }` (reused object, valid during the call). Not an integer ≥ 1, or a throw → 1 and `invalid-span`. Called per row of a declaring column, not for covered rows (HTML table). 2D spans allowed.
3. Grouped headers: nested `ColumnGroupDef { id, header, children }` in `columns` (ARCHITECTURE); the base only flattens to leaves (~90 B). `headerBands(tree, visibleColumns)` in the spans entry: per level an array of fragments `{ group, first, count, label }`; a group is cut at segment boundaries and non-adjacent gaps; a hidden leaf shrinks it; each fragment repeats the label (O7). A column with no group has no cell in the group rows; its leaf header is stretched upward by CSS only.
4. Full-width rows: `settings.fullWidth?: (row: Readonly<T>) => boolean | { part?: string }`, row-level. One cell crossing the pinned segments; still a data node (identity, sorted, filtered). RowKind already lists 'full-width', 'group', 'detail'.
Invariants (property-tested): I1 no overlap; I2 each visible slot has exactly one owner or belongs to a full-width row's single cell; I3 a span lies inside one segment, inside the displayed rows (page) and inside a data-row run (a non-data node or a level change cuts it); I4 origin = top-start cell; I5 pure and deterministic. `merge` with `rowSpan`/`colSpan` on the same column is refused.
Problems (four new codes, one conformance problems case each): `invalid-span` (error), `span-overlap` (warning; the later span drops to 1x1), `span-clipped` (warning; cut at a pinned segment or the end of the rows; told once per layout change), `invalid-column-group` (error; empty group, duplicate id). Capped at 10 per column + summary. Also `missing-feature` when span rules are present without the feature.

## B. Rendering under virtualisation
A span cell is a real cell in its origin row: ARIA ownership, DOM order = aria-rowindex order, one focus identity (origin row key + origin column). Covered slots get no element.
Window: wanted rows = window rows + origin rows of `spans.coveringAbove(first)` (≤ 1 per span column). `RowRenderer.render(f, wanted, retained)` takes `retained: readonly RowKey[]` (focused row + anchors); only the focused row is never moved in the DOM (S10); anchors may move.
Pooling: rows keyed by RowKey; pool high-water rises by ≤ span columns; a row's unchanged test gains spanMap.version; `#fillCell` writes aria-rowspan, aria-colspan, data-span (null removes them).
Geometry: tall cells clipped to the window + overscan, never their full extent (element height caps ~33M/17M px; a run may be a million rows). The cell sits in its origin row with inset-block-start and block-size in layer coordinates (v.top, f.base); the same formula works for a far anchor under the S11 clamp. Extents from the row layout (offsetOf(i+n) − offsetOf(i)), preparing S3 variable heights. A retained focused span that does not reach the window collapses to one row slot. The label is an inner element `position: sticky; inset-block-start: var(--dzg-header-h)` inside a span cell using `overflow: clip` (O1).
Stacking: a row hosting a rowspan cell sets data-spans → `contain: style` only; span cells z-index 1 (above row tints, below pinned segments z 2 and header z 3); the merged cell is transparent so each covered row's tint shows through. Hard case: a tall cell inside a pinned segment (sticky segments are stacking contexts): plan = rows hosting spans paint backgrounds on cells, not segments; host segments z 3, header z 4 — S12 must prove it; fallback: continuation fragments (aria-hidden slot fillers in covered rows, semantic cell in the origin row). Span CSS ships in the feature, not LAYOUT_CSS.
Column window: the centre window widened to the origins of colspans crossing its edge per row (`spans.inRow`); width = sum of covered widths; position offsetOf(origin); spans never cross sticky boundaries (I3).
RTL: all logical; group-label stick offset uses --dzg-start-w.
Full-width row: segments hidden; one `.dzg-fullcell` sticky at inline start, as wide as the viewport (--dzg-view-w); the selection box column stays.
Retained rows S10/S11: focused row at its true position bounded to ±2·REBASE; anchors within one window of the view, never clamped; geometry relative to the actual v.top.
Performance: no spans → one null check; with spans O(log n) per window row, no new DOM reads, guarded writes; benches: merge index 1M rows ≤ 25 ms; 100k data-span calls ≤ 20 ms; a 33 x 20 paint with three merged columns ≤ 1.5x the plain paint.

## C. Keyboard and focus
One tab stop per spanned cell. FocusPos keeps `{row, column}` naming the origin. Header levels signed: negative = group rows above the leaf row, 0 = leaf headers, positive = extras.
Navigation moves out of the router: `apply()` in keys/router.ts becomes pure `moveFocus(map | null, shape, from, goal, intent)` in core (no-behaviour-change extraction). Goal-based: goal = {rowKey, colIndex} kept in the router; vertical moves use goal.col, horizontal use goal.row; Down from a span → origin.row + rows; Up → owner of row−1; Left/Right step by cols; landing on a tall cell focuses its origin but keeps the goal row; PageUp/Down from goal.row; Home/End owner of first/last slot in the goal row; Ctrl+Home/End first/last row; the goal resets when kernel.focus is not what the router last set; in a full-width row Left/Right/Home/End stay put and the goal column is remembered.
Reconcile: `reconcileFocus(f, before, after, columns, owner?)` — a focus on a covered slot after sort/update moves to its origin; the kernel gets the hook via @dzgrid/core/internal `setFocusOwner`, set by the DOM spans feature.
Selection per row: Space on a span toggles the origin row; a click on a tall cell selects the row under the pointer (from y via the layout); cellClicked/rowClicked carry that row; Shift-range uses it (O2).

## D. Accessibility
Body: span cell gets aria-rowspan/aria-colspan (≥ 2 only) and aria-colindex of its origin (shifted by the selection column); covered slots absent; rows keep exact aria-rowindex. No duplicated values by default. Add a protocol step to docs/a11y-protocol.md (NVDA/JAWS/VoiceOver/TalkBack by ear). If a major reader pair loses the value on covered rows: `spans.a11y: 'repeat'` (visually hidden gridcell repeating the text), only if the protocol demands it (O10).
Chrome caveat (S4: a detail row's cell attaches to column 1 and ignores aria-colspan): a full-width cell carries its whole text itself; aria-colindex=1 and aria-colspan=colcount for engines that honour them; check in scripts/browser.mjs via spikes/s4-a11y/ax.mjs.
Grouped headers: group rows role=row, aria-rowindex 1..depth; group cells columnheader with aria-colindex/aria-colspan, no aria-sort, not sortable; leaf row keeps columnheaders; body aria-rowindex starts at depth + 1 + extras + 1; aria-rowcount includes group rows; no aria-level. Frame.headerRows and the painter count group rows.
Announcements: none on focus move; sort/filter unchanged.

## E. Export and copy
CSV (step 10): repeat the value in every covered row (real data; re-import and pivot keep working); `csv.spans: 'first'` for report-style output; XLSX later with real mergeCells. API: `api.spanOf(row, column)` → {row, column, rows, cols} | null; `buildSpanMap` exported from @dzgrid/core/spans. Clipboard HTML later with rowspan/colspan.
