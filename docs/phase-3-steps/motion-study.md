# Motion with GSAP: architect study (2026-10-19)

Owner request: GSAP in DzGrid itself for a "premium" feel; the moments are chosen with the owner. Read: DzGrid, DzCalendar `packages/motion-gsap` + `dom/src/{motion,motion-waapi}.ts` + `docs/motion.md` (sister project), GSAP's public licence page. Decisions, when taken, go in `motion-decisions.md`.

## 0. DzCalendar's pattern
`@dzcalendar/dom` has a `MotionAdapter` (optional hooks beforeChange/afterChange, eventsEnter/eventsLeave, captureLayout/animateLayout, overlayOpen/overlayClose, destroy), `WAAPI_MOTION` default (< 1 kB) and `NO_MOTION`; `@dzcalendar/motion-gsap` = `createGsapMotion(opts)`, `peerDependencies: gsap ^3.13.0`, MIT; `dom/test/no-gsap.test.ts` fails if any dom file mentions gsap; size line "motion-gsap (without gsap)" 3 600 B. Reduced motion: `gsap.matchMedia` created lazily at the first hook, `reduce` starts true, every hook starts `if (!watching()) return`; `destroy()` finishes tweens (`progress(1)`), reverts matchMedia, resets (one adapter serves several instances). Transform and opacity only, `clearProps`, never `visibility`, at most 150 animated nodes, per-effect switches, presets SOBER (default) / EXPRESSIVE, paid plugins given by the app. Tests: real gsap in jsdom, matchMedia stubbed, assertions on `gsap.globalTimeline.getChildren()` / `getTweensOf`. Its licence check (K.10) is still open.

## 1. Catalogue (verdicts)
Body rows are pooled `RowView.el`; `RowRenderer.mounted` maps key → RowView for the window; `keyOf(el)`; rows placed by `inset-block-start` (clamped for scaled scrolling); FLIP on `getBoundingClientRect` is unaffected by the 33M px scaling. Main risk: a pooled row rebound to another key mid-tween.
- Popup / filter popup open — good: fade + 4 px rise + slight scale, 140 ms, one tween; focus already moved; logical origin (RTL).
- Popup close — risky (needs a delayed `el.remove()` in popup.ts: focus-return risk); keep instant.
- Overlay fade — good, fade-in only (never delay `hidden`: live region and Retry are the truth); CSS tier enough.
- Loading skeleton shimmer — risky, no skeleton exists; out of scope.
- Row reorder after sort (FLIP on the window) — good once the pooling guard is tested: snapshot rects of mounted rows, tween `y` after paint; newly mounted rows fade in; leaving rows just vanish; cap 60 rows; skip after a scroll or a big keyboard jump; ≤ 300 ms; off under reduced motion; DOM order already final (screen readers, aria-rowindex right).
- Rows entering/leaving after a filter — good for enter + move (fade 120 ms, short stagger, cap 20), no for leave (recycled in the same paint); skip when paints come under 150 ms apart (typing).
- Value-change flash (insert/update/delete) — good with a rate cap: per updated cell in the window, only on paints after a rows update (never on scroll), non-colour cue, at most one flash per cell per 500 ms, none within 150 ms of scrolling; reduced motion: a static mark 600 ms or nothing (owner). Currently Phase 8 in ARCHITECTURE (row 412).
- Selection — CSS only (80 ms background transition exists, dzgrid.css:323); no drag-range animation.
- Header sort mark rotation — CSS only (state from an attribute).
- Column resize — no for the drag; risky for auto-fit (width reflows).
- Column move / pin — risky (headers only, later).
- Group expand/collapse — good when groups exist (same FLIP).
- Page change — good: slide/fade the body 200 ms, one tween; direction follows RTL.
- Tooltip — CSS only (do not delay the keyboard tooltip).
- Travelling span label — no (fights per-frame repositioning; motion sickness).
- Floating summary, empty state — CSS only / the overlay fade.
Proposed first set: popup open, overlay fade-in, sort/filter FLIP (move + enter), value-change flash, page change slide, plus CSS touches (sort mark, tooltip, floating summary).

## 2. Architecture
A third optional entry `@dzgrid/dom/motion-gsap`, as an ordinary `GridFeature` (id `motion`, `features: [motion({ preset: 'sober' })]`), plus a CSS tier in the theme. No separate adapter interface (features.ts gives setup/destroy/afterRows).
- CSS tier (theme, no JS) inside `@media (prefers-reduced-motion: no-preference)` near dzgrid.css:323: popup open (`@starting-style` or keyframe), overlay fade-in, tooltip and floating-summary fade, sort-mark rotation (~300–400 B gz).
- GSAP tier: sort/filter FLIP, flash, page slide, popup spring.
- No WAAPI middle tier now (code written against a small `play(el, from, to)` helper so it can be swapped later).
- Options: grid setting `motion: false` (runtime, read in update()); `motion({ effects: { flash: false, … } })`; presets sober (default) / expressive later. Reduced motion as DzCalendar (lazy matchMedia, reduce true at start); the CSS tier follows the media query natively.
- Base: everything exists (key → element via `g.rowRenderer.mounted` and `keyOf`, context.ts:64, rows.ts:160,475; `FeatureHandle.afterRows` at viewport.ts:213; kernel `modelUpdated` kind rows for value changes, diffing displayed text in the window; the kernel event fires before the frame so rects can be read then — except in sync mode; a MutationObserver on `g.el.root` sees `.dzg-popup`; overlay via `hidden` or CSS). One seam to add: `FeatureHandle.beforeRows?(): void` called in viewport.ts just before `rowRenderer.render` (deterministic snapshot incl. sync mode; reads only when armed by a kernel event, never on scroll paints): ~40–70 B gz → ask dom 18 750 → 18 850. Without it: arm from the kernel event only (zero base bytes, weaker tests). Popup exit animation not included (~80 B in popup.ts later if wanted).
- GSAP rules: transform/opacity only, `clearProps` on complete, never `visibility`/layout properties; pooled-row guard (remember the key per tweened element; in afterRows, if `keyOf(el)` changed, `progress(1)`/kill and clear first); skip FLIP if > 60 rows move, after a scroll between snapshot and paint, or a scaled jump > a screen; flash only after rows updates, ≤ 1 per cell per 500 ms, none within 150 ms of a scroll; tweens on gsap's own ticker, reads in beforeRows / the kernel event, writes in afterRows (reads before writes once per frame); `lagSmoothing` untouched; `destroy()` finishes tweens, reverts matchMedia, clears maps; one `motion()` may serve several grids.
- Peer: `peerDependencies: { gsap: "^3.13.0" }`, `peerDependenciesMeta: { gsap: { optional: true } }`; only the entry imports gsap; a `no-gsap.test.ts` for the rest of dom, core, theme.
- Licence (plainly): GSAP is not MIT nor OSI open source; it is under GSAP's "Standard License" (Webflow): free including commercial use, plugins such as Flip included; restrictions: no use in visual no-code animation tools competing with Webflow's builder, no reverse engineering to build competitors, keep notices, Webflow may terminate on breach. Nothing forbids a data grid. DzGrid stays MIT (gsap is an optional peer, none of it shipped). Not legal advice; same open question as DzCalendar's K.10; action: ask GSAP's contact and record the answer in ARCHITECTURE. Consumers install GSAP and accept its licence.
- Sizes: entry 3 000–4 500 B gz (gsap and dom external; `over: @dzgrid/dom`, `external: ["gsap","gsap/*","@dzgrid/core","@dzgrid/core/internal"]`), ask 4 500 for the first set; GSAP recorded apart (`gsap kit: core`, `gsap kit: core + Flip`, via `without`): core ~25–30 kB, Flip ~8–10 kB more (to measure); FLIP by hand (as DzCalendar's `fromRect`) so only gsap core is needed. Theme CSS tier +350 (1 800 → 2 150). Locales: none.
- Tests: jsdom with real gsap and matchMedia stubbed: reduced motion adds no tween; `motion: false` none; effect switches; destroy mid-tween leaves no inline transform/opacity; one instance serves two grids; pooled-row guard; cap 60; no tween on a scroll-only paint; flash rate cap; first paint animates nothing; sync-mode test of beforeRows (once per paint, before render); no-gsap test; size lines. Browser: no layout reads during the tween (wrapped getBoundingClientRect/offsetHeight counts), activeElement unchanged across a sort FLIP and a popup open, tab order and aria-rowindex untouched, long-animation-frame < 50 ms during a 300-row-window sort (perf-browser.mjs), RTL page for popup and page slide. Behaviour sheet `docs/behaviors/motion.md` first.
