## 1. Facts that shape the design (read in the code at `7ceb9c9`)

1. **Column state already exists in the core.** `ColumnState { id, width?, hidden?, pinned?, order? }`, `ColumnModel.state()` / `apply(patch)` (`core/src/columns/model.ts:17-45`), kernel command `column.state` (any patch, one `columnsChanged` event, the focus leaves a hidden column, `kernel.ts:655`), `column.resize`, `columns.set` keeping the user's state by id. `ColumnDef.movable` is declared (`defs.ts:35`) but read nowhere. **Moving, hiding, pinning and widths therefore need no core base code**: an order patch is enough.
2. **Everything `GridState` needs is readable from the kernel**: `query` (sort, filter, quick, one canonical `key`), `columns.state()`, `expansion` (a live set: copy it), `selection`, `focus`, the page through the model; and every change has its event (`sortChanged`, `filterChanged`, `quickChanged`, `columnsChanged`, `columnResized`, `pageChanged`, `rowExpanded`, `selectionChanged`). `query.set` sets sort + filter + quick in **one** command (one server request). A filter change sends the pages back to the first: a restore must set the page **after** the query. Whether `query.set` then `page.go` costs one or two server requests is not known yet: a restore must cost **at most one** (`grid-state.md` 7); **step 5** counts it and adds the joining seam only if it is two.
3. **Feature seams** (`dom/src/features.ts`): `decorateHeader` (the ⋮ button goes there, like the filter button), `keys`, `headerRows` (rows under the column headers, focus `{kind:'header', level ≥ 1}`, already keyboard-reachable: the floating filter row), `bands` (group rows, the spans feature), `afterRows`, parts. A feature gets `g.el.*` and can listen on the header itself: **pointer drag of headers needs no base code**.
4. **`@dzgrid/dom/popup`** (1 472 / 1 650) gives top-layer popups, Escape, focus return, modal Tab trap, outside-press close: the menu and the chooser sit `over` it.
5. **Key conflicts found.** (a) **Alt+ArrowDown on a header is already the filter popup's** (`filters/menu.ts:105`, owner decision O2); ARCH §2.8 gives the same key to the column menu. (b) **F2 on a header is taken** by the stale-order reapply when `@dzgrid/dom/edit` is loaded (`edit/stale.ts:91`): the resize mode cannot use F2. (c) ARCH's « Alt+Shift+arrow » to move a column: on Windows, Alt+Shift is the default « switch input language » shortcut (it fires on release of the pair, often with an arrow too); Arabic users have two layouts. Key choice in D3.
6. **One `g.layoutFor` per grid.** The detail feature sets it (`detail/index.ts:86`) and deletes it on destroy; an auto-height feature would overwrite it. Auto height with details needs the two composed (a base change, D9).
7. **Density is done**: `density: 'compact' | 'comfortable' | 'spacious'` (28 / 32 / 40 px) and `rowHeight` (24–1 000), live, grown with the reader's text size, anchor kept (`virtual-scroll.md` « Row height »). Phase 6 only adds a way for the **user** to switch it (D10) and its place in `GridState`.
8. **Header groups exist** (`ColumnGroupDef { id, header, children }`, flattened by the base, bands drawn by `@dzgrid/dom/spans`), with no collapse. Collapsing hides children; the base `shown` filter (`model.ts:78`) knows only `hidden`. Using `hidden` for collapse would mix the user's choice with the group's state (a user re-showing a column would open half a group; `GridState` could not tell them apart). D6.
9. **Print**: only `@media print { .dzg-resize, .dzg-tooltip { display:none } }` in the theme. A virtual grid prints its window only: `preparePrint()` must draw every row (or a cap) outside the virtual scroller.
10. **Autosize**: not built. The resize sheet names « double-click the edge », not implemented (`interact/resize.ts` has no double click). ARCH §2.1: measure in the read phase, a deterministic sample.
11. **S3 rule** (ROADMAP spikes): auto height is free up to 10 000 rows (0 px jump in three engines), Firefox ≤ 1.5 px at 100 000, 365–508 px without correction: a developer warning above 10 000, measures batched in one rAF read.
12. **Margins** (ROADMAP « Final budgets (Phase 5) »): core 84 B (28 916 / 29 000), dom base 415 B (21 565 / 21 980), Angular 187 B (6 813 / 7 000), `dom/spans` 495 B (4 455 / 4 950), `core/spans` 362 B, theme base 256 B (2 494 / 2 750), **K.8 guard 514 B** (82 986 / 83 500), **real Angular example 441 B** (92 059 / 92 500). Any base growth lands in K.8 and the example too.
13. **Sehhaty** (`docs/sehhaty-track.md`): `admin/audit-logs` keeps its state **in the URL** today (sort, filters, page). That makes `GridState` + a URL helper the first Sehhaty need of this phase; the rest is asked (Q-S).

## 2. Decisions to take (D1…D14; the owner's answers win)

- **D1 entries** (Q-B): every Phase 6 feature is an optional entry, so a base grid pays nothing: `@dzgrid/core/state` (pure: capture, check, restore, JSON), `@dzgrid/dom/state` (persist: debounced `stateChanged`, URL and `localStorage` helpers), `@dzgrid/dom/columns` (moving by pointer and keyboard, keyboard resize mode, auto-size), `@dzgrid/dom/column-menu` (over `/popup`), `@dzgrid/dom/columns-panel` (the chooser, over `/popup`), `@dzgrid/dom/pinned-rows`, `@dzgrid/dom/auto-height`, `@dzgrid/dom/print`; collapsible groups inside the existing `core/spans` + `dom/spans`. Texts `locales/{en,fr,ar}-columns` (menu, chooser, move / resize / state sentences) and `-print`; styles `@dzgrid/theme/columns.css` (menu, chooser, drag marker, pinned rows), `print.css`. The base gains seams only (D6, D8, D9), each measured.
- **D2 column moving by pointer** (sheet `column-move.md`): drag a header (pointer down + 4 px, mouse and pen; touch: long press 500 ms or no drag at all, Q-M); a ghost of the header follows, an insertion bar (≥ 2 px, ≥ 3:1) shows where it lands, logical (RTL mirrored); auto-scroll near the edges; Escape cancels; dropping in a pinned segment pins it (start / end), out of it unpins; `movable: false` columns do not move and keep their place (others cannot land before a locked column at a segment's edge; the sheet fixes the exact rule); a column in a group may leave it, the group then shows on each side with its label repeated (already `spans.md`). One `column.state` patch per drop (one `columnsChanged`, source `user`). WCAG 2.5.7: the menu's « move left / right » and the keyboard (D3) are the no-drag ways.
- **D3 column moving by keyboard** (Q-K): on a focused header, a modifier + Left / Right moves the column one place (logical: Right in RTL moves toward the end), Home / End to the edge of its segment; one polite sentence « Nom : colonne 3 sur 9 ». Key options: Ctrl+Shift+Left/Right (★, no OS conflict on headers, the range feature does not act on headers), Alt+Shift (ARCH, Windows layout switch risk, fact 5c), or only through the menu.
- **D4 keyboard resize mode** (exit criterion; Q-K): entered from the column menu (« Redimensionner ») and by a key on a focused header (Ctrl+Alt+R? or Alt+R; **not F2**, fact 5b); in the mode, Left / Right change the width by 10 px (Shift: 1 px; logical: wider toward the end in RTL), Home = auto-size, Enter / Escape leave (Escape restores the width), Tab leaves; the header shows the mode (outline + `aria-description` « mode redimensionner »), one sentence per change, throttled (« Nom : 140 pixels »). The resize handle stays `aria-hidden` (one way in, not a second tab stop). `columnResized` `finished: false` per key, `true` on leaving.
- **D5 auto-size** (Q-M1, Q-K3): `autoSize(columns?)` and `autoSizeAll()`; double-click on the resize edge; menu items « Ajuster cette colonne / toutes ». Measures header text + the cells' text: the mounted rows + a deterministic sample (first 200 displayed rows, formatted through the column's formatter, measured with one off-screen element per font in one read phase, never per cell layout reads); clamped by min/max; a resized column stops being flexible (`resize.md`); custom parts measured only when mounted. « Fit to width » (shrink all to the view) as an option, not default.
- **D6 collapsible header groups** (sheet amendment `spans.md`): `ColumnGroupDef.collapsible?: boolean`, `open?: boolean` (initial), child `ColumnDef.groupShow?: 'open' | 'closed'` (shown only when the group is open / closed; absent: always). A button in the group header (`aria-expanded`, Enter / Space on the focused group header, ≥ 24 px). The collapse is **its own state** in the column model, not `hidden` (fact 8): the base `shown` filter reads one extra set (core base seam ~40–80 B, Q-B), so `GridState` saves `groups: { [id]: open }` apart from the user's hidden columns. Focus on a column that closes moves to its group header.
- **D7 the column menu** (Q-M): a ⋮ button at the header's inline end (≥ 24 px, shown on hover / focus, always on touch; `aria-haspopup="menu"`), right-click on a header, and a key (Q-K: Alt+ArrowDown when the filters feature is absent; with it, Alt+ArrowDown keeps opening the filter (O2) and the menu takes **Shift+F10 / the Menu key on a header** ★, or Alt+ArrowDown opens the menu whose first item is « Filtrer… »). Contents (Q-M, ★ set): Trier croissant / décroissant / sans tri; Épingler au début / à la fin / ne pas épingler (radio); Ajuster cette colonne / toutes; Redimensionner (D4); Déplacer vers le début / la fin (one place, D2's no-drag way); Masquer la colonne; Choisir les colonnes… (opens D8); Filtrer… (when filters are there); Réinitialiser les colonnes; the host's own items (`items(col, defaults) => MenuItem[]`, label, icon part, action, disabled, checked). APG menu: arrows, Home/End, type-ahead, Escape returns to the header, submenus none in this phase (radio groups instead). Parts: `menu.button`, `menu.item` replaceable (Tailwind / Bootstrap classes through `ui` like `headerClass`).
- **D8 the column chooser** (Q-C, Q-H): a list of all columns (groups as indented, collapsible sections), a **search box** (accent- and case-insensitive, Arabic folding as the quick search), a **checkbox** per column (disabled for a column the app marks `hideable: false`, and for the last shown column, O1), « Tout afficher » (no « Tout masquer », O1), « Réinitialiser », and **reordering** by drag handles (pointer, a finger too, O5), by ▲ / ▼ buttons on each row (the single-pointer way, WCAG 2.5.7) and by keyboard (Alt+Up / Alt+Down on a focused row; a list of native checkboxes, not a listbox: `columns-chooser.md`). **New `ColumnDef` fields, type-only (0 B)**: `hideable`, `menu: false` (no ⋮ menu for that column), `chooser: false` (left out of the chooser), with a polite sentence. Changes apply live (one `column.state` per gesture) or on « Appliquer » (Q-C). Shell: a **dialog** (modal popup anchored to the menu item or to a host button: `openColumnChooser(anchor?)`) ★, or a **side panel** inside the grid's root (a tool bar with « Colonnes » / « Filtres » tabs, ARCH §2.8). The filters tab of the side panel: Q-C (★ later, Phase 9 with the advanced filter).
- **D9 auto row height** (Q-R): per column `wrap: true` (the cell wraps; `autoHeight` implied) or grid `rowHeight: 'auto'`; the feature measures the mounted rows' heights in one rAF read after the paint (no layout read during writes), hands a `variableRowLayout` through `g.layoutFor` with the density / `rowHeight` as the estimate and floor; the anchor (S3) keeps the top row; above 10 000 rows a developer warning (`problems`, `auto-height-large`) and still works (S3 « estimate and correct »). **Base seam**: `g.layoutFor` becomes a small chain so detail panels and auto heights compose (fact 6; dom base ~80–150 B). Re-measured on: data change of a row, column width change, language, text size. Pinned parents (tree) copy their row's height. Not with `rowHeight` number: `rowHeight` wins if both (Q-R).
- **D10 density for the user** (Q-R): a menu item group « Densité : compacte / normale / aérée » (radio) in the column menu's grid section, and/or `setDensity()` for the host's own toolbar (★ the API and an optional menu item); saved in `GridState` (`density`) when the user changed it.
- **D11 GridState** (Q-S): shape (versioned, JSON-safe, **no row data**; ARCH §3.14 narrowed to what exists):
  `{ v: 1, columns: ColumnState[] (id, width, hidden, pinned 'start'|'end'|null, order), groups?: {id: open}, sort, filter, quick?, page?, pageSize?, expanded?: RowKey[], selected?: SelectionState, density?, scroll?: { row: RowKey, offset } }` — which parts are saved by default is Q-S. `captureState(kernel, opts)` and `restoreState(kernel, state, opts) → Problem[]` in `@dzgrid/core/state`: unknown version → `state-version` problem, nothing applied; unknown column → skipped with `state-column` (warning); bad field → that field skipped; restore order: columns → groups → one `query.set` → page size → page → expansion → selection → focus / scroll; one `stateRestored` event. Logical sides and ids only, so **an LTR state restores identically in RTL** (exit criterion; property test both ways). Where (Q-S2): the app gets JSON (`state()` / `setState()` / `stateChanged` debounced 300 ms) ★ plus tiny helpers in `@dzgrid/dom/state`: `persistLocal(grid, key)` and `toSearchParams` / `fromSearchParams` (for the audit screen's URL), never a cookie, never row data.
- **D12 the group drop zone, split 6 / 7** (Q-G): Phase 6 builds the **drag source and the drop protocol** in `/columns` (a header dragged out of the header row can be dropped on a registered target: `dropTargets.add(el, { accept(col), drop(col) })`, highlight, keyboard path through the menu) and writes the zone's sheet (`group-zone.md`: chips « Nom × », reorder, remove, empty text « Glissez une colonne ici pour regrouper », keyboard). **Phase 7** ships `@dzgrid/dom/group-zone` with grouping, and adds « Regrouper par cette colonne » to the column menu. Nothing about grouping is visible in Phase 6 ★; option: ship the empty zone in 6 behind a flag (no use without grouping).
- **D13 pinned rows** (Q-P): `pinnedRows: { top?: T[]; bottom?: T[] }` (live; their own `getRowId` space prefixed so keys never clash), drawn with the columns' cell parts and formats, aligned with pinned columns and horizontal scroll, never sorted, filtered, paged or counted (`aria-rowcount` counts them as rows: decided in the sheet); not selectable; ~~not editable in this phase ★~~ **editable (owner Q-P = C, see « Owner decisions applied »)**; CSV: optional `include: 'pinned'` later. Top rows use the existing `headerRows` seam (focus `{kind:'header', level}`, keyboard already crosses it); bottom rows need a **base seam** (a sticky foot row group under the body, `footRows` like `headerRows`, and the router's Down / Up / Ctrl+End across it: dom base ~200–300 B, core focus 0–40 B for a « foot » level). Typical use: a totals row (Phase 7 aggregation will feed it).
- **D14 print** (Q-I): `preparePrint({ maxRows = 5 000, title? }) → Promise<() => void>` in `@dzgrid/dom/print`: draws the displayed rows (filtered, sorted, in order) as a real `<table>` (thead repeated on each page, logical sides, `dir` kept, pinned columns first in reading order, no virtualisation) in a print-only container, then the host calls `window.print()` (or `print()` does both and cleans up on `afterprint`). Above `maxRows`: `print-too-many` problem and the first `maxRows` printed with a line saying so. Cells as text (formatted), parts printed as text (`ui` part's text), no colours needed (`print.css`: borders, page breaks inside rows avoided). Server pages: the current page only ★ (all pages = an export, not print).
