## 1. Facts that shape the design (read in the code at `31381ed`)
1. **Nothing of editing exists yet.** No `core/edit`, no `@dzgrid/dom/editors` entry (not in `packages/dom/package.json` exports nor `size-budget.json`), no `editable` on `ColumnDef` (`core/src/columns/defs.ts`), no `edit.*` setting (`dom/src/settings.ts`), no copy or paste at all (no clipboard listener anywhere). `dzg-cell--saving|saved|failed|invalid` are named in ARCH §3.11 and `docs/behaviors/cell-class.md` only, not in code or theme. The viewport carries a hard-wired `aria-readonly="true"` (`dom/src/grid.ts:71`).
2. **The overlay seam is there, half wired.** `ValueReader` (`defs.ts:133`) is read by sorting and filtering (`model/column-cache.ts`) and by the CSV writer (`csv/writers.ts:59`). `ClientModel.setReader()` takes a reader without reordering and `reapply()` re-runs filter and sort and notifies `'order'` (`model/client.ts:226-228, 743-753`): K.14 holds in the client model. But: `setReader`/`reapply` are not on the `RowModel` interface (the source/server models have none), there is no kernel command for them, and **the DOM paint reads `col.read(row)` directly** (`dom/src/render/rows.ts:85`), so an edit would not show in a cell today.
3. **Keys.** `KeyOwner` already has `'editor'`; `ownerOf` (`dom/src/keys/owner.ts`) classes any control inside a cell as `'cell-widget'` *before* `'editor'`, so the grid's editor must mark itself `data-dzg-owner="editor"` (the comment says so). `INTENT_OWNERS` gives the `editor` owner no intent: Enter, Tab, Escape inside an editor are the editors feature's own job. On a cell, Enter and F2 are `enter` (a part's `focus()`), Escape `leave` (from a widget only), and every Shift combination returns null (« ranges come in Phase 4 », `core/src/keys/intent.ts`). Features' `keys?(e, at, owner)` run before `intentFor` (`dom/src/keys/router.ts:117`); the tree and detail hooks already return false unless `owner === 'cell'` (`tree/index.ts:255`, `detail/index.ts:255`). A nested grid's keys are filtered by `closest('.dzg') !== root`.
4. **Retained row contract** (ARCH, after Phase 0): (5) a retained row is updated like any other, *except the cell being edited*; (6) to close an editor, focus the cell first, then remove the input.
5. **Row kinds.** `RowNode = DataNode | GroupNode (fillers) | DetailNode | LoadingNode` (`core/src/row/node.ts`); selection, select-all, Shift ranges and CSV already skip non-data rows.
6. **Trees.** `parentId(row)` and `path(row)` are host functions over the **raw** row (`core/src/tree/shape.ts:12-16`); the overlay never feeds them, so an edit can never move a tree row through the reader.
7. **Context.** `settings.context` is DOM-only: parts, `canSelect`, `canExport`, tooltips (step 21 Q3: « not filter kinds' test/wire, value getters or sort »). `FilterKind.test(s, ctx)` gets the `LocaleCtx` (`filter/kind.ts:22`, `filter/compile.ts:128`); the kernel's `context.set` is the locale context. Giving the app context to filters and sort means carrying it into the kernel and model env (core API change).
8. **Motion.** `onCell(el, c, 'changed')` only; `'saving' | 'saved' | 'failed'` reserved (`dom/src/motion-gsap/index.ts:58`); flash ≤ 50 cells per paint, from transactions.
9. **Angular.** Two-way state uses `model()` with echo guards (`quick`, `filter`, `selected`, `expanded`, `packages/angular/src/grid.ts:107-111`); no forms, no ControlValueAccessor. Custom parts go through `dzgPart` / `componentPart`.
10. **Margins under the owner's grants** (ROADMAP « Final budgets (Phase 4) »): core 760 B (28 240 / 29 000; seam guard pinned at 28 240 in `core/test/layering.test.ts:104`), dom 652 B (20 648 / 21 300), angular 12 B, dom/tree 36 B, core/detail 6 B, theme 232 B, motion run 296 B, real Angular example ~3 kB (86 988 / 90 000), K.8 guard 3.2 kB (80 286 / 83 500).
11. **ARCH §6's scope for editing is large**: editors, validation, saves, undo/redo, range selection, copy/cut/paste, fill handle, Ctrl+D/Ctrl+R, bulk edit; exit criteria: bugs 1–5 of ngx-sheetgrid `a6c97f5` replayed by tests that failed first, dataset B (3 000 × 12) bulk edit ≤ 30 ms with **one** save request, paste of 1 000 cells ≤ 40 ms, Ctrl+V/Ctrl+Z/Escape in an editor never act on the grid, rollback never touches the source, range and fill handle right in RTL. It makes `pharma/stock` possible (ARCH §2.10). `docs/sehhaty-track.md` records no editing need yet.

## 2. Decisions D1–D16 (the owner's answers win)
- **D1 scope and split** (Q1): Part A, cell editing (editors, validation, saves, K.14, undo/redo, trees/details/nested); Part B, ranges and clipboard (range selection, copy/cut/paste, fill handle, Ctrl+D/R, bulk edit, dataset B). One phase, Part A gated and committed before Part B; Part B's step plans written after Part A's close. Out of this phase: full-row editing, popup editor, rich list with search (Q15), editing on a tree's structure (Q13).
- **D2 core layout**: the base gains seams only (types and guards): `ColumnDef.editable?: boolean | ((row, context) => boolean)`, `ColumnDef.validate?` (type), `RowModel.setReader?` / `reapply?` (optional, client today), kernel commands `edits.reader {reader}` and `rows.reapply` (source `user` or `host`), kernel state `orderStale: boolean` (true when the reader changed a sorted or filtered column since the last run), event `orderStale {stale}`; `editableAt(node, col, context)` = `node.kind === 'data'` and the column says yes. Everything else in a new entry `@dzgrid/core/edit`: the save coordinator (ARCH §3.10 rules 1–6, ported from our `cell-edits.ts` with the six changes listed in ARCH §3.0), the overlay reader (version bumped per change, `Map<RowKey, Map<column, PendingCell>>`), the undo stack (100 batches), validators (`required`, `min`, `max`, `pattern`, codes only). Part B: `@dzgrid/core/range` (range by keys, TSV codec, `planPaste`, fill plan, bulk plan).
- **D3 overlay everywhere**: the DOM paint reads through the reader (`g.reader`, one branch in `cellValue`; `NO_OVERLAY` keeps the uniform path identical); sort, filter, CSV already do. Rows move only on `reapply()` (K.14, `reapplyAfterEdit: false`); `orderStale` drives a discreet mark and the reapply gesture (Q6, Q7).
- **D4 starting an edit** (Q4): on an editable data cell, F2, Enter (unless the cell has an interactive part: Enter enters it, F2 still edits), a printable key (replaces the text; the key is the first character, composition-safe), double click; Delete/Backspace on a cell clears it (one save, origin `edit`). Not on a single click. A non-editable cell: nothing, `aria-readonly="true"` on it once any column is editable (the viewport's hard-wired attribute becomes computed).
- **D5 ending an edit** (Q3, Q5): Enter commits and moves per `edit.enterMoves: 'down' | 'stay'` (owner default), Shift+Enter commits and moves up; Tab / Shift+Tab commit and move to the next / previous editable cell in reading order (`edit.tab: 'cell' | 'grid'`, ARCH §2.5); Escape cancels and keeps the focus on the cell; blur (click elsewhere) commits (Q5). Closing follows contract (6). Inside an editor, Ctrl+Z, Ctrl+V, Escape, arrows belong to the field (ARCH exit criterion).
- **D6 validation** (Q9, owner's variant): every refusal (local or server) shows a ~0.5 s red, blinking border on the cell (theme CSS, `dzg-cell--refused`; reduced motion or `data-motion="off"`: still red border). A local refusal (validator or codec parse failure, `value-input.md`) keeps the editor open with the typed text, `aria-invalid="true"`, message bubble linked by `aria-describedby`, one sentence (assertive, e.g. « Stock : valeur refusée, nombre attendu »); Escape cancels. Server refusal: D7. Paste/fill (Part B): refused cells skipped and counted in one sentence. Sheet `edit-validation.md`.
- **D7 saves**: `edit({ save })` host handler `(req, signal) => Promise<void> | void`; one gesture = one request; per-cell queue; global generations; rollback to `lastSaved`, never `previousValue`, never the source rows; `onSource` from transactions and from server answers; a rejected save (server refusal, Q9) → after the 0.5 s refusal animation the cell shows its last saved value, an error mark stays (reason on hover and focus), `saveFailed` event with the original error unchanged, one assertive sentence; retry by reopening the cell (the refused text offered). Cell states as classes `dzg-cell--pending|saving|saved|failed|invalid|refused` and, while saving, the cell's description says « saving » (no `aria-busy` on cells); announcements: the pending state once per gesture (polite, Q10 amended), refusal assertive, success silent (the flash; listening §19 may change it). Sheet `edit-save.md`.
- **D8 edited row that no longer matches** (Q6, Q8): it stays where it is until `reapply()`, muted like a tree context row (`data-dzg-stale`), never selected away; at reapply it leaves (focus to the nearest row, existing fallback). An editor open on a row that a host transaction or a server answer removes: closed, the typed value dropped, said once; a row only hidden (still held): the typed value kept as a pending edit.
- **D9 animated save states** (Q10 B, amended): the theme draws static, non-colour-only marks (pending dot, brief check, error sign that stays; CSS, forced colours, reduced motion safe). **Running border while saving** (decided): on by default, `edit({ savingBorder: false })` switches it off; reduced motion or `data-motion="off"` → a still border; never announced; still after 5 s of saving (WCAG 2.2.2); stops at once on saved / refused, then the flash or the refusal animation. Step 1 architect's pick: CSS in the theme (class `dzg-cell--saving` written by the base from the overlay, conic-gradient ring turned by an `@property`, reversed in RTL), so it works with pooled rows and scrolling and without GSAP; checked at step 7 in three engines. `motion()` activates the reserved reasons `onCell(el, c, 'saving' | 'saved' | 'failed')` under the same guards (≤ 50 per paint); built-in `saved` reuses the flash. Motion run grant 3 500.
- **D10 undo/redo** (Q11): Ctrl/Cmd+Z, Ctrl+Y and Ctrl/Cmd+Shift+Z on the grid (not in an editor); undoing a saved cell is a new edit (origin `undo`), ignored with a sentence if the cell changed since; stack cleared on `getRowId` or model change; API `edit.undo()`, `redo()`, `canUndo`, `canRedo`.
- **D11 non-data rows**: details, fillers, loading rows are never editable, pasteable, fillable; `editableAt` refuses them in the core (one guard, conformance cases); `planPaste` steps over them without consuming a source line (ARCH §3.0 « lignes sans donnée enjambées »); a range's rows are keys, non-data rows inside a range are skipped by copy, paste, fill and bulk. Carried test: Phase 4 criterion 5 (details not editable / pasteable).
- **D12 trees** (Q13): an editor in the tree column owns Left/Right (the tree hook already ignores non-`cell` owners: a test pins it); the indent and toggle stay outside the input (the editor fills the content box after the indent). A column feeding `parentId`/`path` is not editable in this phase (`edit-structure` problem, Q13 option A).
- **D13 nested grids**: each grid has its own coordinator, undo stack, keys and clipboard routing (document listeners routed by `activeElement` to the nearest `.dzg` root); editing a master never touches its detail; Ctrl+Z in an inner grid undoes the inner grid only.
- **D14 context for filters and sort** (Q12): `kernel` gains `app.context` (`context.app {value}` command, from `settings.context`), handed to `FilterKind.test(s, ctx, context)`, custom comparators and `editable` / `validate`; a context change refilters (a host action, not an edit, so rows may move).
- **D15 i18n, RTL, a11y**: `locales/{en,fr,ar}-edit` (saving, saved, failed, retry, undo/redo said, stale order, `validation.<code>`, refused count, row removed while editing), 0 B in the base bundles; editor fields `dir="auto"` for free text, numbers and days isolated (`dir="ltr"` inside an RTL cell, caret logical), Arabic-Indic digits read by the codecs; IME: Enter and Escape during composition (`isComposing`, keyCode 229) are the IME's; accessible name of the field = column header + row header; save marks never colour-only; fill handle (Part B) ≥ 24 px; §19 of `docs/a11y-protocol.md` (fr/ar by ear, the owner).
- **D16 Angular** (Q17): column `editable` and `validate` pass through; inputs `save` (handler) and `editing` (options); outputs `cellEdited`, `saveFailed`, `orderStale`; custom editors by `<ng-template dzgEditor="col">` / `componentPart` on the `editor.<name>` slot; no forms, no ControlValueAccessor; a test-zone test for zero turns during a save tween.
