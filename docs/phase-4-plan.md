# Phase 4 plan: tree view and master/detail first, then the floating-row toggle, then editing (architect, 2026-10-21)

Decisions on top: `docs/phase-4-steps/decisions.md` (they win). Clean room: behaviour from WAI-ARIA 1.2 (treegrid, aria-level/posinset/setsize/expanded), the APG treegrid pattern, WCAG 2.2; sheets in `docs/behaviors/` first, in our own words. Byte and time figures are targets to measure.

## 1. Facts that shape the design
1. `RowNode<T> = DataNode<T>` today, but `RowKind` lists group | footer | detail | full-width | loading, `DataNode.level` exists, `groupKey(path)` and `detailKey(master)` exist in ids.ts.
2. `DisplayedRows` is the only view the DOM sees (nodeAt, keyAt, indexOf, index, nextData); `ClientModel.show()` builds it (`flatDisplayed`): the seam for tree and detail rows.
3. Uniform row height is hard-wired in six places: viewport.ts (mapper height d.count*h, anchor at*h+delta, uniformRowLayout(d,h), topIndex floor(logicalTop/h)), keys/focus.ts ensureVisible i*h, interact/scrolling.ts h, keys/router.ts page size, motion flip "mounted × h". RowLayout (offsetOf, heightOf, indexAt, setHeight) and a Fenwick variableRowLayout exist in core, unused.
4. Focus is cell-only; Left/Right = column moves (mirrored in RTL by intentFor); a rule for expand/collapse with cell focus is needed.
5. Seams reused: FeatureHandle (afterRows, beforeRows, decorateHeader, headerRows), enter/leave intents, cell-widget owner, data-dzg-owner read first, the retained row, scrollMapper (any logical height), anchorNext, the Part system (Angular exposes every slot).
6. `ModelChange.kind` gains `'expand'`.

## 2. Decisions D1–D12
- D1 the tree is a view: tree rows are data rows (d: keys); `ExpansionState = ReadonlySet<RowKey>` in the kernel, outside Query/Query.key (no page, selection or request reset); commands `rows.expand {rows, expanded}`, `rows.expandAll {expanded, depth?}`; event `rowExpanded {source, rows, expanded}` (keys only, one per bulk change); `kernel.expansion`; `RowModel.setExpansion?(set, source)` re-flattens only; pruned on transaction removed; `tree.initial: 'none' | 'all' | number` at the first non-empty load; persistence into GridState in Phase 5.
- D2 the shape seam: `RowShape<T> { build({ snap, order, matched, filterActive, expansion, version }): DisplayedRows<T>; all?(): DisplayedRows<T> }`, `ClientOptions.shape?`, `ClientModel.setExpansion`; DisplayedRows optional `parentOf?(key)`, `levelAt?`; `RowNode = DataNode | GroupNode | DetailNode` (type-only; DOM guards kind === 'data'). Tree: filter → build → per-level sort (one global sort, stable bucketing by parent, O(n)) → flatten expanded nodes into Uint32Array ids + Uint8Array level + Int32Array ordinal/siblings; fillers ids ≥ snap.count; expand = splice, never re-sort/filter. Detail: one DetailNode (`x:` + master key) after each expanded master over the filtered, sorted, paged order; paging works with detail; paging with a tree refused (`unsupported-combination`).
- D3 tree shapes, in order: `parentId` (orphan → root + `tree-orphan`; cycle → unreachable rows appended as roots + `tree-cycle`, iterative), `children` (nested arrays flattened; unique getRowId, `duplicate-row-id`), `path: (row) => string[]` (missing segments → filler group nodes `groupKey(path)`, not selectable/editable).
- D4 filtering: keep ancestors of matches (ARCH §3.13); non-matching ancestors muted (`data-context-row`); while a filter/search is active the flatten opens ancestors of matches without touching the user's expansion (restored on clear); counts.filtered = matches; option `tree.filter: 'ancestors' | 'subtree'` (owner Q3).
- D5 selection: independent by default; select-all takes visible data rows; fillers and details never selected; Shift ranges skip non-data; collapsing keeps hidden selected rows; cascade with tri-state → owner Q2 (`selection.tree: 'cascade'`, fully loaded client trees only); headerSelection and allDisplayed skip non-data (base).
- D6 tree cell and keys: decoration of the first visible column (or `tree.column`) via afterRows: `padding-inline-start: level × indent`, a decorative toggle `<span class="dzg-toggle" aria-hidden>` with a 24 px hit area, not a tab stop; chevron to the inline end when collapsed (CSS mirrors in RTL); pointer clicks on the toggle taken by a capture listener (stopPropagation). Row attributes aria-level (1-based), aria-posinset, aria-setsize (visible siblings after a filter; -1 for unknown lazy sizes), aria-expanded (parents); viewport role `treegrid`. Base seam `FeatureHandle.keys?(e, at, owner): boolean` before intentFor; in the tree column: forward on a collapsed parent expands (else column move); back on an expanded parent collapses, on a collapsed parent or a leaf with a parent focuses the parent row same column; `*` expands siblings; Enter/Space unchanged; a collapse hiding the focus moves it to the nearest visible ancestor (parentOf); `tree-column-not-first` warning if the tree column isn't first. Announcements `tree.expanded {name, n}`, `tree.collapsed {name}` (bundles `locales/{en,fr,ar}-tree`).
- D7 variable heights: one `RowLayout` per paint (`g.layoutFor?.(d, h) ?? uniformRowLayout(d, h)`), only total/offsetOf/indexAt/heightOf used; total feeds scrollMapper; anchor/top-row via offsetOf/indexAt; ensureVisible, wheel and page keys read `g.layout`; new `sparseRowLayout(rows, h, extras)` in `@dzgrid/core/detail` (binary search over D open details + prefix sums, no N-Fenwick; setHeight O(D)); variableRowLayout kept for Phase 5 auto height; a detail height change above the viewport sets anchorNext.
- D8 detail: `DetailNode {key: x:<master>, kind:'detail', level, master, data}`; base `#bind` builds one `dzg-dcell` (role gridcell, aria-colspan = columns) exposed as `RowView.slot`, row `data-kind="detail"`; content = new part slot `'detail'` (context row, key, master key, ctx, dir, msg, announce, context, height info), lazy mount on first expansion, destroyed on collapse or leaving the window (Angular free via dzgPart/componentPart); heights `detail.height: number | (master) => number | 'auto'` (auto: ResizeObserver → layout.setHeight after an estimate; a nested grid needs fixed/function); focus: Down from the master reaches the detail cell (accessible name from the master), `MoveShape.whole?(rowIndex)` (Left/Right/Home/End stay; goal column kept), Enter/F2 → the part's focus(), Escape → back; the content container `data-dzg-owner="cell-widget"`; not selectable, copyable, editable, pasteable, exported; no rowClicked/cellClicked; a nested-grid part with an LRU (default 20) of `{query, scrollTop}` per master; soft depth cap 3 (problem past it); tree + detail on one grid not in Phase 4 (`unsupported-combination`).
- D9 spans disabled with tree or detail (`unsupported-combination`, conformance case).
- D10 lazy children: A client recipe (`tree.hasChildren`, rowExpanded + applyTransaction add, a loading child row kind 'loading' with aria-busy, abort on collapse, an error row with retry); B first-class in `sourceRows` (`children(req: ChildRequest)`, gate channel `children:<parentKey>`, new epoch collapses all and clears the cache) — B per owner Q6.
- D11 export: CSV of a tree via `allRows` in tree order (collapsed descendants included; displayed = visible rows); fillers as label-only rows; `csv.tree: 'none' | 'level' | 'indent'` default 'level'; details never exported; server trees via exportAll.
- D12 motion: `'expand'` → rows below glide (flip), new rows fade (cap 20), collapse instant (step 6: the rows below glide up too, `step06-plan.md`), skip > 60 moved, none under reduced motion; flip's screen measure from `g.viewBlock` (~20 B base); detail open/close reuse open effects (verify).

## 3. Steps
Part A — tree: 1 sheets (tree-view, tree-keys, tree-filter, tree-selection, master-detail, floating-toggle; selection, csv-export, motion, a11y-protocol §16 treegrid §17 detail), spike S12 (1M rows, 2 000 open details of 240 px, Chrome/Firefox/WebKit: row 999 999 reachable, 0 offset error at both ends, wheel and PageDown correct, retained-row focus kept, resize above the viewport keeps the top row; drift → documented cap), budget decision (owner). 2 core base seams (node union, displayed parentOf/levelAt, client shape/setExpansion/'expand', kernel expansion + commands + event + focus fallback + non-data skip; tests incl. a base-size test; core +800–900 vs 1 016 headroom). 3 `@dzgrid/core/tree` parent mode (+ conformance; property test 1 000 seeded trees vs a recursive oracle; targets build 100k ≤ 40 ms, expand 10 000 children ≤ 30 ms, filter 100k ≤ 60 ms). 4 DOM base seams (`FeatureHandle.keys?`, `g.layoutFor?`, 'expand' anchoring, `g.viewBlock`) + `@dzgrid/dom/tree` (role, attributes, decoration, pointer capture, keys mirrored in RTL, announcements; theme toggle/context row/forced colours; browser axe fr/ar RTL, ≥ 24 px, 100k tree). 5 nested and path shapes, filler rules, selection (independent; cascade per Q2), CSV tree. 6 motion expand + the million-row tree (`perf/profiles/tree.ts`, playground/tree.html; 1M build ≤ 1 s, 60 fps). 7 lazy children (A; B per Q6; 1 000 permutations).
Part B — master/detail: 8 `@dzgrid/core/detail` (shaper, sparseRowLayout vs a brute-force oracle; ≤ 900 B). 9 DOM base for variable rows and the whole-row kind (layout seam for real, detail row, `whole` in moveFocus, offsets in focus/scrolling, slot 'detail'; the uniform paint byte-identical in behaviour, perf guard). 10 `@dzgrid/dom/detail` (feature, nestedGrid part, LRU, height modes; tests: lazy mount/destroy, auto height once per resize, top row kept, Down/Enter/Escape, outer router ignores inner keys incl. Escape bubbling, LRU restore and cap, not selectable/exported, depth 2 ok/4 problem, no row data in events, SSR; browser axe, wheel chaining, 1M masters, 200 details opened). 11 Angular (`[(expanded)]` echo-guarded, dzgPart/componentPart 'detail', tree/detail features; example).
Part C: 12 live floating-row toggle (`filters().floating: { get(); set(on); bind(button) }`, Angular `[floatingFilters]`; typed filters stay active when hidden (header mark says so), a pending edit flushed on hide, a focus in the row moves to the column header, showing restores inputs without emitting; tests incl. aria-rowcount/rowindex, RTL, axe; +150–250 in /filters).
Part D: editing, planned separately after step 12 (ARCH §3.10, K.14): Enter in an editor (option `edit.enterMoves`, owner default), an edited row that disappears (rows move only on `reapply()`), animated save states (onCell hook), context for filter tests and sort (core API change after a budget decision), edits that change a parent/path move rows only on reapply, details not editable.
13 the Phase 4 close (Parts A–C): rebudget, full gate, owner listening §16–§17, README/CHANGELOG 0.2.0 unpublished, STATUS, ARCHITECTURE ("Décisions de la Phase 4", tree/detail leave Phase 6).

## 6. Risks
Scaled scrolling with unequal heights (spike S12 first; cap if needed); screen readers on treegrid (speak expand/collapse ourselves; owner listening); flattening performance (CSR O(n); path tries O(n·depth) — intern segments; lazy indexOf back-map; splice not rebuild); core headroom 1 016 B (measure at step 2, then Q7); lazy loading and the gate (per-parent channels, epoch kills all, collapse during a request, collapse everything on epoch); nested grids (memory, focus, inner keys, wheel chaining, ResizeObserver loops, destroy during scroll); a11y of a whole-row stop (accessible name from the master); RowNode widening (type change; guards; API tests); selection semantics (cascade later must keep SelectionState a key set); K.14 (edits changing a parent move rows only on reapply).
