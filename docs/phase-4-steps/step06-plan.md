# Step 6 plan: motion for tree expand/collapse, the million-row tree (lead, 2026-10-21)

Plan: `docs/phase-4-plan.md` D12, step 6, exit criteria (« 1M-row tree at frame rate with row 999 999 reachable »). Sheets: `docs/behaviors/motion.md` (Trees and details), `tree-view.md`. Step 26 rules stand (`docs/phase-3-steps/step26-motion-blueprint.md`, `step26-decisions.md`): transform and opacity only, no layout read, the pooled-row guard, `clearProps` of `transform,opacity,--dzg-flash` only.

## Decisions and reasons

1. **Arming.** The run chunk's model subscription (`g.rows.subscribe`, the seam a sort already uses) arms a new bit on `kind: 'expand'`. `beforeRows` snapshots the offsets the grid wrote (plus a running glide's `y`), as for a sort. The painter's `'expand'` anchoring (step 4: the top row stays) runs before the snapshot is compared, so only the rows below the toggled parent move. A sort and a toggle in the same frame: the sort's glide wins (one effect).
2. **Open.** Rows below glide down from their old offset (y only, 300 ms, the same tween as a sort); the rows new to the window (the children) fade in, staggered, at most 20 (more: they simply show).
3. **Close: rows below glide up** (the caller's scope; D12 and the sheet said « instant »: the sheet is corrected). The hidden rows get nothing (their elements are pooled and shown for other rows; the guard finishes anything on them). Rows that come into the window at the bottom are rows below too: they glide up by the same distance as the lowest row that moved (in one toggle every row below moves by the hidden block); none moved in the window (the hidden block taller than it): they simply show.
4. **Skips**: more than 60 rows gliding (the bottom rows counted), a row moving more than a screen (`g.viewBlock`, no read; that row only), a scroll between the change and the paint (`g.scrolledAt`, or the layer moved: the anchor scrolled), reduced motion (nothing at all: no hook, no still mark — a toggle has no information to keep), `settings.motion: false`. Not the 150 ms typing rule of a sort: a key held on → or ← glides each toggle from where the rows are (their `y` is read in the snapshot), never a jump.
5. **Switch** `effects.expand` (default true) covers both the glide and the fade of a toggle; `flip` and `enter` stay the sort's. As for every switch, `onRow` is still called: reasons `'moved'` and `'entered'` now cover expand too (the contexts are the same).
6. **`expandAll`** is not told apart (the model change carries no count of rows toggled): the caps decide — a whole tree opening is more than 20 entering rows or 60 moving ones, so nothing moves; a small tree glides. The sheet says so instead of « skipped for expandAll ».
7. **The chevron** turns by CSS only, in the theme: `transition: rotate 120ms` on `.dzg-toggle::before`, inside `prefers-reduced-motion: no-preference` and `.dzg:not([data-motion=off])`, and only in a hovered or focused row (`.dzg-row:is(:hover, :focus-within)`): a pooled toggle shown for another row while scrolling must not spin. The toggle is the pointer's target (hover) or in the focused row (keys).
8. **Sizes**: the expand effect in the run chunk (≈ +150–250 B, budget 2 900, measured 2 589); the shell gets the `expand` switch type only (0 B); theme +~60 B (2 101 / 2 500); `@dzgrid/dom` and `@dzgrid/dom/tree` 0.
9. **The million-row tree**: `perf/profiles/tree.ts` (seeded, parent ids, 10 roots breadth first, ten levels, mixed widths: 35 % leaves, most parents 1–6 children, some 5–14, 0.5 % 100–199). Node lines: build 1M cold (the client model from the rows: store, parents, order, flatten), expand-all 1M from all closed, filter 1M (number filter, ancestors kept and opened); the toggle line at 1M kept. Chrome (`npm run bench:browser -- --only tree`, a new filter): the full tree opened, a 2 s wheel scroll (LoAF, frame times), a toggle near the top and one near the end (to the paint), Ctrl+End reaching row 999 999 with `aria-rowcount` right. Budgets: measured first, new lines only, Node +10 %, Chrome +35 % (rebudget rules); a missed target is reported, not hidden.
10. **Pages**: `playground/tree.html?rows=1000000` uses the profile; the browser tree page takes `profile=1&rows=1000000` for the bench; the motion demo page gets an « Arbre » section (a small tree with motion) if it stays cheap.

## Tests first (`packages/dom/test/motion-expand.test.ts`)
Open: rows below get a y tween from −Δ (moved), the children an opacity tween (entered), the parent and rows above nothing; at most 20 fade. Close: rows below glide from +Δ, rows entering at the bottom too, the hidden rows nothing. Skips: > 60 rows, Δ over a screen, a scroll between change and paint, reduced motion (no tween, no hook, no mark), `motion: false`, `effects.expand: false` (hooks still called). Hooks `'moved'`/`'entered'` on expand; `false` suppresses. Focus, `aria-expanded`, DOM order and `aria-rowindex` equal to a `motion: false` twin mid-glide; nothing left inline at the end; the pooled-row guard (a scroll mid-glide finishes and clears). Theme: the chevron transition only under no-preference and not `data-motion=off`. Bench and browser lines as above; browser `--only motion` extended with a toggle.
