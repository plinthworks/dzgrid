# The filter user interface

## What the user does
Types into a box under a column header; clicks the filter button in a header, or presses Alt+ArrowDown on it; picks an operator, a day, or ticks values in a list; presses Escape.

## What they observe
- A row of filter boxes under the headers, for the columns that ask for one: text and number columns get a box that filters as you type; the others get a summary button that opens the column's popup.
- The filter popup sits under the header and holds the column's filter: an operator and a value for text and number, all / yes / no for a boolean, an operator and one or two dates for a day or an instant, a searchable checklist for a value list.
- The value list has a search box, "select all (shown)" and "blanks". When the server filters, it waits for an Apply button; everywhere else a change applies at once.
- A filtered column shows a mark in its header, and its name says so.
- Escape closes the popup and puts focus back where it opened from. Inside a filter box, arrows, Home, End, Ctrl+A, Enter and Space edit the text and never move through the grid.
- The new row count is announced.

## What DzGrid does
- Matching rules are not repeated here: see `filter-text.md`, `filter-number.md`, `filter-day.md`, `filter-instant.md`, `filter-misc.md`.
- **Floating row** (step 12, `@dzgrid/dom/filters`): off by default, turned on per column (`filter.floating: true`) or for the grid (`filters({ floating: true })`); `filter.floating: false` keeps one column out. The row is fixed when the grid is made (owner decision O3): it exists when the grid option is on or any column, hidden ones included, asks for it; a column without a floating filter gets an empty cell, so every header row holds the same columns. It is a header row (counted in `aria-rowcount` and `aria-rowindex`), its cells `role="gridcell"` at level 1 of the grid's roving order: Down from a column header goes to it, then to the first row; Up comes back the same way, through the group rows above. Enter or F2 on the cell goes into its control (the box's text selected), Escape inside goes back to the cell and keeps the filter. Inside the box (`data-dzg-owner="filter-input"`) arrows, Home, End, Ctrl+A, Space and Enter stay in the box; Enter applies at once and stays. The controls of a floating cell are out of the Tab order (one tab stop for the grid) until Enter or F2. A click there never sorts, shows no tooltip, has no resize grip.
- **The box:** `type="text"` (never `type=number`), `autocomplete="off"`, no spell check, no placeholder, named `filter.inputLabel {column}`; a number box has `inputmode="decimal"`. Its cell carries `aria-readonly="false"` (the grid says read-only). The text follows its own direction (`dir="auto"`, `unicode-bidi: plaintext`, aligned at the start).
- **What the box edits** (owner decision O3): a text box edits "contains" (null or `{type: 'text', op: 'contains'}`, keeping `caseSensitive`); a number box edits "equals" (null or `{type: 'number', op: 'equals'}`). Any other filter on that column (another operator, between, blank, a combined filter) shows the summary instead.
- **Live apply with a pause:** 300 ms when the filter runs on the server, 150 ms in the browser; `filter.debounceMs` on the column, then `filters({ debounceMs })`, override it (not a finite number of 0 or more: the default). One pending edit per column, replaced by the next; Enter, Escape, leaving the cell and the cell leaving the window apply it at once; destroying the grid drops it. An emptied box removes the column's filter (the built-in boxes never store an empty filter). Text is applied as typed (no trim). Typing in an input method applies when the composition ends.
- **Numbers:** read in the grid's locale (`readNumber`): `1,5` in French, `١٫٥` and `1.5` in Arabic, `12%` as 0.12. A number that cannot be read is not applied (the filter in force stays); it is judged when the edit would apply, not per keystroke (`-` on the way to `-5` is not flagged): the box gets `aria-invalid="true"`, a 2 px outline (not only a colour) and one announcement `filter.invalid {column}`; typing again clears it.
- **Echo:** the box keeps the form it last sent; the same filter coming back leaves the text alone (`1,50` is not rewritten under the caret). Another filter (the host's `filter.set`, Clear, the overlay's clear-all) rewrites it, a number in the locale without grouping; text typed and not yet applied is left alone.
- **On a server:** only the pause differs; an empty edit on an unfiltered column and an unreadable number send nothing; an everything-except selection follows the kernel's rule (`server-selection.md`).
- **Summary** (step 12, owner decision O4): for day, instant, boolean, set and custom kinds without a `floating.<kind>` part, and for a filter the box cannot edit. With a filter in force: the short, static text `filter.summaryActive` ("Filter active") and a Clear button named `filter.clear {column}` that removes the column's filter at once and puts focus back on the cell; without one, an empty cell. Step 13 turns it into the button opening the popup.
- **Popup:** opened by the header filter button (a target of at least 24 px) or by Alt+ArrowDown on the header (`openMenu`, owner `header`). Clicking the button never sorts. Operators follow the column type, narrowed by `filter.ops`; "Clear" empties the column's filter. A second condition with AND/OR may be cut to Phase 5 (the model keeps `combined`).
- **Value list:** a `listbox` with `aria-multiselectable`, virtualised beyond 2 000 values (`aria-setsize`, `aria-posinset`). Ticking fewer than half gives `include`, more gives `exclude`; the search narrows the list, never the filter. Values come from the rows held when the filter runs in the browser (counts over the other filters and the browser's search, never this column's own), from the source's `values()` when it runs on the server (never from the rows held; a stale answer is dropped), or from `enumOptions` when the server has no `values`. A value with no row is not offered, except one already ticked (`value-list.md`).
- **Day and instant:** the native date input by default (a date-picker adapter can replace it). A wall time that a clock change skips is refused with `filter.timeSkipped`, never shifted.
- **Top layer:** the popup is shown with `popover="manual"` when the browser has it, `position: fixed` in the grid otherwise, so a host card with `overflow` or `transform` cannot clip it. It is a modal `dialog`: focus goes in, Tab stays inside, a pointer down outside does not close it. Escape closes it without reaching a host dialog around the grid, and focus goes back to the anchor; if the anchor left the page (header recycled, column hidden), the popup closes and focus returns to the grid's focused cell.
- **Keys:** a filter box carries `data-dzg-owner="filter-input"` and owns every key; popup controls carry `popup`. A grid inside a host popup still owns its own keys.
- **RTL:** the popup's start edge lines up with the anchor's start edge, on the right in Arabic, and it opens above when there is no room below. It carries the grid's `dir`; inputs follow the logical order.
- **Active mark:** a `data-dzg-filtered` mark on the header plus `filter.active` in its accessible name.
- **Button and mark are decorations** (step 11, decision O4): the filters feature puts the filter button and the active mark in the header cell beside the sort mark, through a header decoration seam (`FeatureHandle.decorateHeader`, step 13). They are never the content of a `header` part, so a host's header part keeps them.
- **Announcements:** after a user's filter change, `announce.filtered {rows}` with the filtered count (`announce.rows`); on a server, once the answer is in (a failed fetch says nothing more); `announce.filteredOpen` when the count is unknown.
- **Texts in their own bundles** (owner decision O1): `@dzgrid/dom/locales/{en,fr,ar}-filters`, spread by the host into its messages (`text: { ...FR.text, ...FR_FILTERS.text }`); the base bundles do not grow. `filters()` throws a `TypeError` naming any missing filter key when the grid is made.
- **Clear all** (the overlay's `clearFilters()`): one `query.set` keeping the sort, so a server is asked once.

## Decisions (step 1, 2026-10-17)
- **Names:** the floating row is `filter.floating` per column and `filters({ floating })` for the grid; the date picker is `filters({ datePicker })`. The plan's `floatingFilter` and `adapter` are superseded.
- **Apply button** whenever `filter` runs on the server, fetched set included (B5.6). Pending ticks stay pending until Apply; closing the popup discards them.
- **Where focus returns:** to the popup's anchor — the filter button when it opened from it, the header cell after Alt+ArrowDown. If the anchor left the page, the grid's focused cell.
- **Popup name:** `aria-label`, as the popup host does, from the new key `filter.popupLabel {column}`. No `aria-labelledby` on the header text: the header can be recycled and its name carries the sort state.
- **Initial focus:** the filter part's `focus()` when it returns true, else the first focusable control (the popup host's default). The filters feature calls it after mounting the part.
- **Pointer down outside** a filter popup does not close it (it is modal, as the code does); nothing pending is applied.
- **Summary text:** a value list reads `filter.summarySelected {n}` (plural); every other kind `filter.summaryActive {column}` when active and `filter.summaryNone {column}` when not.
- **Header name:** the filtered state joins the name through `header.withFilter {header}`, applied after `header.withSort` when both hold; `aria-label` is set only when one of them holds, as today.
- **Announcement on a server:** after the accepted answer, `announce.filtered {rows}` with `counts.filtered`; when the server does not know the count, `announce.filteredOpen`. Nothing is said while it loads beyond `aria-busy`.
- **Clear all filters:** only the no-match overlay's `clearFilters()` in Phase 3; a host clears with `filter.set {}`.
- **Escape in a floating box** returns focus to its cell and keeps the typed filter; tested at step 12.
