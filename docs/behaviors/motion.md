# Motion

## What the user does
Sorts by a header, types a filter, turns the page, opens a filter popup, or watches a grid whose values the application updates live (prices, beds free, results arriving). Some users have asked their system to reduce motion; some use a screen reader or a high-contrast mode.

## What they observe
- After a sort or a filter, the rows that stay on screen glide to their new place (at most 300 ms); rows that come into view fade in; rows that leave just vanish. The order, the focus and what a screen reader reads are already the new ones from the first frame.
- A page change slides the rows a little (24 px, 200 ms) from the side the reading goes to: from the end side for the next page (the left in Arabic), from the start side for the previous one.
- A value the application changes live is tinted for a moment, with a short bar at the cell's start edge (not colour alone); many values changed at once, or while the user scrolls, are not marked. A row the application adds live fades in once, as a row (its cells are not tinted).
- A filter popup and the grid's overlay (loading, no rows) fade in with a small rise; a popup closes at once.
- With reduced motion asked: nothing moves, nothing fades (a row added live simply shows); a value changed live keeps a still mark for 0.6 s, counted again from a second change. In forced colours the mark is drawn in the system's highlight colour.
- The first paint, a scroll, a reload of all rows, typing fast in a filter: nothing animates.

## What DzGrid does
- **An optional entry** `@dzgrid/dom/motion-gsap`: `motion({ preset?: 'sober', effects?: { flip?, enter?, flash?, page?, popup? }, gsap?, onCell?, onRow? })`, a grid feature. GSAP is an optional peer the application installs (`gsap ^3.13`); none of it is in `@dzgrid/dom`. The feature's eager part is small; the tweens and GSAP itself are a chunk loaded in idle time after the first rows are painted (or at `load()`); effects before it arrives are skipped (owner Q1). One `motion()` may serve several grids.
- **Transform and opacity only** (and the `--dzg-flash` variable with the `dzg-flash` class): never a layout property, never `visibility` or `hidden`. A tween ends by removing exactly `transform`, `opacity` and `--dzg-flash`, so the inline sizes and offsets the grid writes stay. No layout read: a row's old place is the offset the grid wrote, taken just before the rows are placed (`beforeRows`).
- **Rows glide** (`flip`, `enter`) after a sort or a filter (the model's `order` or `query` change): the rows mounted before and after move by the difference of their offsets, y only; entering rows fade in (120 ms, staggered), at most 20 — more, and the window is mostly new: it simply shows (a frame stays short). Skipped: more than 60 rows moving, a row moving more than a screen (that row only), a scroll between the change and the paint, an armed paint less than 150 ms after the previous one (typing).
- **Pooled rows**: a row or cell element shown again for another row or column has its effects finished and cleared before anything else (the grid recycles its elements): every tween on it, the host hook's included, and whatever they left inline of `transform`, `opacity`, `--dzg-flash`. An element a hook or an effect touched is followed until then (or until it leaves the page, or the grid is destroyed), whatever the hook answered.
- **Value flash** (`flash`): only after a live change of rows (owner Q3): a transaction the application applied (`update`, `add`), or a `rows` update that replaces only a few rows (the model reports both as the same delta); never after a full reload (a reset: more than half the rows new); the same row and column whose displayed text changed, in rows that were there before (owner Q5: a row added live gets one row effect instead, the `enter` fade with `onRow(el, c, 'entered')`, at most 20 in a paint, none under reduced motion, and none of its cells is marked); at most 50 cells in a paint (more: none), at most one per cell (row key and column, whatever element shows it) every 500 ms, none within 150 ms of a scroll. It is not announced.
  - **After a full reload** (step 16e): with `sameRow` (row-identity-transactions.md « Rows compared by value »), a full reload or a server's answer flashes only the cells that changed; without it a full reload stays a reset and nothing flashes.
  - **Its colour** (step 16, owner: « la couleur, on peut donner ce qu'on veut et par thème »): `--dzg-flash-color`, by default the palette's warning (amber), a hue apart from a selected row and a block of cells (the accent), so a flash right after a fill shows in dark too (the accent tint at 18 % over the block's 14 % read as « no animation »). A theme sets its own, light and dark (theming.md).
  - **Its duration** (1.1.0, the owner's tree screen; step 14): `effects.flash: { hold, fade }` in ms — the mark is set at full at once, held `hold` ms, then fades to nothing in `fade` ms. `true`, absent or `{}` = today: `{ hold: 0, fade: 600 }`. Each field a finite number from 0 to 10 000; anything else (negative, `NaN`, a string, over 10 000) takes that field's default and tells one `invalid-setting` warning per grid and field (path `motion.effects.flash.hold` or `.fade`, detail the value as text), never a throw; it is read when the motion chunk loads (idle time), so the warning comes then. Under reduced motion: a still mark for `hold + fade`, no fade (owner Q14-5). The saved flash (below) uses the same durations (owner Q14-6). A cell changed again: the 500 ms cap is unchanged (a change within 500 ms of the last mark is not marked again, the running mark goes on); after it, the mark restarts at full with a full hold — the running one is replaced, never two on one cell — so a value that changes every second stays lit. A pooled cell shown for another row loses its mark at once, as before.
- **Page slide** (`page`): the rows' layer, sign from the direction and the page moved; an unknown page fades only; not on the first paint.
- **Popups and overlay** (`popup`; owner Q2): a popup opening (its content: fade and a 4 px rise; the popup element itself, fixed or in the top layer, is never touched) and the overlay appearing (a fade) are animated by GSAP once the chunk is there (before, they simply appear); the popup host has already placed it and moved the focus; the motion never touches the focus; close is instant.
- **Switches**: `settings.motion: false` (live) stops every effect, finishes those running, keeps the chunk from loading, and sets `data-motion="off"` on the grid's root (the theme's motion rules honour it). Each effect has its switch in `effects`.
- **Reduced motion** is followed live (`gsap.matchMedia`, reduce assumed until it answers); a change finishes the effects running.
- **The host hook**: `onCell(el, c, 'changed')` and `onRow(el, c, 'entered' | 'moved')` hand the element to the application's own GSAP code, after DzGrid's guards (armed, not scrolling, caps, at most 50 calls per paint). `c` carries the key, the row, the column (id), the value and its text (and the previous text), `context` and `reduced`. Returning `false` means handled: the built-in effect is skipped. A hook may animate `el` only (transform, opacity, `--dzg-*`, classes); a pooled element's hook tweens are finished like the grid's (pass the same `gsap` as `motion({ gsap })`). A throw is reported. Under reduced motion only `changed` (and the saves' reasons, below) are called, with `reduced: true`. Reasons `saving`, `saved`, `failed`: the saves (Phase 5 step 7, below).
- **GSAP missing**: the grid works, without motion, and tells one problem (`missing-feature`, path `features.motion`, detail `gsap`).
- **Destroyed**: the effects running are finished and cleared, delayed calls killed, the media watch reverted once the last grid goes.

- **Trees and details** (Phase 4, plan D12; step 6 for the tree, done; step 10 for details): a model change `'expand'` (a parent or a master opened or closed), switch `effects.expand` (default true; `flip` and `enter` stay the sort's). Opening: the rows below glide down to their new place (the same glide as a sort, y only, 300 ms) and the rows that appear fade in (at most 20; more simply show). Closing: the rows below glide up, the rows coming into the window at the bottom with them (by the distance of the lowest row that moved; none moved: they simply show); the hidden rows get nothing, nothing fades (step 6 decision: D12 said « closing instant »). Skipped: more than 60 rows gliding, a row moving more than a screen (that row), a scroll between the change and the paint, reduced motion (nothing at all: no hook, no still mark), `settings.motion: false`. Not the 150 ms typing rule: a key held on → glides each toggle from where the rows are. Open or close is told by the expansion change itself (the kernel's `rowExpanded` and its `expanded` flag), never by the row count (a transaction may land in the same paint); an opening and a closing in one paint (or a change not told by the kernel): a plain glide, nothing fades, nothing rises at the bottom. A close arriving mid-glide: the rows coming in at the bottom rise by the hidden block (the offsets the grid wrote), the moved rows from where they are drawn. A toggle and a sort in one paint: the sort governs, one effect plays, under its `flip` switch and its typing rule (lead, step 6 review). `expandAll` is not told apart: the caps decide (a whole tree opening is too many rows: nothing moves). `onRow` is told `'moved'` and `'entered'` for a toggle too. Its `index` is found when the hook reads it: the first read after a toggle in a million-row tree builds the row index (a few ms); a hook that does not read it pays nothing. The flip's screen size is read from the viewport's block size the grid already knows (`g.viewBlock`), not from mounted rows × row height, since rows no longer share one height. The chevron turns by CSS only (the theme, 120 ms, under `prefers-reduced-motion: no-preference` and not `data-motion="off"`, only in the hovered or focused row, so a pooled toggle shown for another row while scrolling never spins). A detail panel opening reuses the popup's open effect on its content (a fade, no rise) — to verify at step 10; closing is instant. Focus, `aria-expanded`, the DOM order and `aria-rowindex` are final before any frame moves.
## Where DzGrid differs on purpose
- Motion is opt-in and never needed to read the grid: the DOM order, `aria-rowindex`, the tab stops and the focus are final before any frame moves.
- Reduced motion keeps the information of a flash (a still mark), not its movement.
- GSAP is not MIT: it comes under GSAP's own "Standard License" (Webflow), accepted by the application that installs it. DzGrid itself stays MIT and ships none of it (ARCHITECTURE).

## Phase 5 step 7: the saves (built 2026-10-24; D9, Q10 B, owner S7-O5)
- With `@dzgrid/dom/edit`, `onCell(el, c, reason)` is also told `saving` (once per gesture and cell, when the
  request leaves), `saved` and `failed` (when the refusal comes), for mounted cells only, at the paint that follows;
  `pending` tells nothing. The cap: more than 50 such cells in one paint (a bulk save) tell none; the 50 hook calls a
  paint are shared with `changed`. A new reason first finishes what the previous one started (a host's long `saving`
  tween included); a pooled cell is finished as before.
- `c.value` / `c.text`: what the cell shows (for `failed`, the refused value during its 0.5 s); `c.previousText`:
  for `failed` the last saved text (what comes back), else the row's own value as the column writes it.
- Built in: `saved` only, the live flash (`dzg-flash`, `--dzg-flash` 1 → 0 in 0.6 s) under `effects.flash`, one per
  cell per 500 ms (shared with the live flash: a cell changed live and saved at once flashes once), none within
  150 ms of a scroll (the hook is still told), `false` from the hook skips it. Reduced motion: the still mark 0.6 s,
  the hooks told `reduced: true`. `motion: false`: nothing, what runs finished. Without `motion()`: the marks alone.
- The run chunk reaches the edits only through the grid's edit seam (`g.edit.api.state`, `g.edit.read`): it never
  imports `@dzgrid/dom/edit` (a structure test).
- Found in Chrome (step 7): clearing a finished tween's props asked GSAP to parse the transform, which reads the
  element's offset parent (a layout read per cell). The guard now clears only what a tween left inline.
