## 1. Facts that shape the design (read in the code at `55b8391`)

1. **One shape per grid, fixed at creation.** `GridFeature.shape?()` is asked once, before the model; the first feature giving one wins (`dom/src/features.ts:21-25`, `35-38`). `ClientOptions.shape` « set once, at creation » (`core/src/model/client.ts:225-226`), `RowShape.kind: 'tree' | 'detail'` (`client.ts:188`). So: (a) a user who regroups at run time needs a shape that is **always there** when the grouping feature is loaded (empty `by` = flat) and changes its own `by`; the redraw path exists: `attach(model, redraw)` (`client.ts:815`, it tells `'expand'`); (b) **grouping + tree, and grouping + master/detail, on one grid are impossible** without composing shapes (the detail feature is a shape too).
2. **A path tree is almost a grouping.** `pathStructure` (`core/src/tree/build.ts:62-123`) builds a trie per level, makes a filler `GroupNode` keyed `groupKey(path)` for each level no row has, O(n·depth), no recursion; `withFillers`, `buckets`, `visibility` and the flatten follow. Measured budgets of that machinery (`perf/budgets.json`): tree build 100 000 rows ≤ 40 ms, expand one parent of 10 000 children ≤ 30 ms (the exit criterion's own number), toggle at 1 000 000 rows ≤ 16 ms. Two differences for grouping: (a) a row **claims** the trie node of its last segment (`build.ts:83-86`), while a grouped row must always be a leaf **under** its group; (b) segments are `String(list[j])` (`build.ts:79`): `1` and `'1'`, `null` and `'null'`, two days with different texts of one instant all collapse or split wrongly. A typed group needs typed segments.
3. **`GroupNode` as built is `{ key, kind, level, label, path }`** (`core/src/row/node.ts:17-24`), not ARCH §3.2's `{ field, value, childCount, expanded, aggregates }`. `'footer'` is in `RowKind` (`node.ts:3`) with no node type. Adding optional fields and a `FooterNode` is types only (0 B).
4. **Keys.** `groupKey(path)` = `g:` + length-prefixed segments (`core/src/ids.ts:72-75`); `isDataKey` takes `d:` only (`ids.ts:135`), `isCellKey` `d` / `p` (`ids.ts:138`); `editable` refuses any non-data node (`core/src/columns/editable.ts:13`). So group rows are **never selected, never in a block, a fill or a paste, never edited — by construction**. Two traps: (a) the same value under two columns gives the same key (`g:5:Alger` for « Wilaya » then for « Commune »): an open group would stay open after regrouping by another column; (b) **a group key holds row values** (a patient's name, if grouped by it): it must never reach a `Problem`, a `GridState`, an address or a log.
5. **What a shape is fed.** A tree sorts every row and gets a match mask (`client.ts:420`, `input = tree ? null : filtered.order`); any other shape gets the **filtered, sorted** order — what grouping wants (groups made of matching rows only). Client pages are refused for trees only (`client.ts:309`); a grouping shape would be paged as details are (rows per page) unless refused. `treeConflicts` already refuses spans, details and pages beside a tree (`core/src/tree/shape.ts:327-328`).
6. **Rebuild cost.** The tree rebuilds its structure whenever the snapshot changes (`tree/shape.ts:66`): any transaction is O(n). ARCH §5.3's « update 1 row: core ≤ 1 ms » is a flat-grid line; grouping must state its own (D15).
7. **Edits (K.14).** An edited value does not move its row; the order is marked stale only when the edit touches a sort, filter or search column (`touches`, `client.ts:356-359`); `setReader` keeps every stage and does not rebuild the shape (`client.ts:785-793`). Grouped as is: an edit of a grouping column would never mark the order stale, and **aggregates would not change** after an edit. Two base seams are needed (D14).
8. **Expansion lives in the kernel already**: `rows.expand` / `rows.expandAll { expanded, depth? }` (`core/src/kernel.ts:604-618`; unknown *data* keys refused, group keys pass, `kernel.ts:607`), one `rowExpanded` per command, `initial: 'none' | 'all' | number`, depth 1 = the roots. Keys of removed data rows leave the open set; group keys stay (`client.ts:537`, `isDataKey`).
9. **The tree painter** (`dom/src/tree/index.ts`): `treegrid` role (`:60`), `aria-level` / `posinset` / `setsize` / `expanded` (`:239-242`), toggle and a filler's label in the tree column (`:259-266`), keys through `intentFor` so forward / back are mirrored in RTL (`:273-292`), `*` (`:172`), pinned parents (`:138`), sentences (`:99`). It reads `TreeRows` (`posAt`, `sizeAt`, `childrenAt`, `expandedAt`, `levelAt`, `parentOf`; `core/src/tree/shape.ts:24-37`): **a grouped rows view that implements `TreeRows` gets every one of these behaviours by reusing the painter's code.**
10. **Group cells are drawn empty.** `#bind` gives a non-data node no data (`dom/src/render/rows.ts:334`); the tree writes a filler's label itself in `afterRows` (`tree/index.ts:259-266`). Aggregates in a group row's cells need either the feature to write them the same way (0 B base) or a base seam (D5).
11. **Exports.** CSV writes a filler as its label in the tree column, with a level column, whenever the rows have `levelAt` (`core/src/csv/chunks.ts:130-157`); every other field of a non-data node is empty (`core/src/csv/writers.ts:59`): **a grouped CSV gets its group lines for free, without aggregates**. Print prints data rows only (`dom/src/print/index.ts:104`, O9): **groups vanish from print** as built.
12. **Drop protocol** (Phase 6): `columns().dropTargets.add(el, { accept, drop, label? }) → remove` (`dom/src/columns/index.ts:25-36`); no keyboard path; a zone needs `@dzgrid/dom/columns` for the drag only (the menu and keys work without it).
13. **Column menu**: features driven through `use: { columns, range, fill, chooser }` and their `api(grid)` (`dom/src/column-menu/index.ts:30-39`), items built at `:172-214`. Measured 4 297 / 4 300: a « Regrouper par cette colonne » item needs a grant.
14. **Hiding grouped columns.** The column model has **one** `folded` set (`core/src/columns/model.ts:52-57`, `:87`, `:185-190`), owned by the header-groups UI, which replaces it whole (`dom/src/groups/index.ts:104`, `:127`, `:129`). A grouping that hid columns through `fold` would fight collapsible header groups; through `hidden` it would mix the user's choice with the grouping's (the Phase 6 plan's fact 8).
15. **GridState.** `groups` already means header groups (`core/src/state/state.ts:39`, `:49`; `grid-state.md` 1); expanded rows are not saved (Q-S1, `grid-state.md` 2). The DOM-held parts come through `StateEnv` adapters (`state.ts:56-69`, `:194-203`). `core/state` measured 1 500 / 1 500 (0 B margin).
16. **Server.** The server model wraps an inner client model with the shape (`core/src/server/rows.ts:147`): a grouping shape there would group **one page** and total it — wrong totals shown as right. ARCH §3.6 (l. 1214) gives Phase 8 a `GroupRequest` whose aggregates come from the server.
17. **Names taken.** `@dzgrid/dom/groups` is the collapsible **header** groups UI (Phase 6 Q8-4, `dom/src/groups.ts`): ARCH §6's `dom/groups` cannot keep its name. `group-drop-zone.md` already names `@dzgrid/dom/group-zone` and the texts `locales/{en,fr,ar}-group`.
18. **Pinned rows** take the host's `T` rows, keyed by `getRowId`, editable (`dom/src/pinned-rows/index.ts:14-27`): a grand total is not a `T` and must never be editable.
19. **Margins** (measured now, `node scripts/size.mjs` at `55b8391`, gzip): core base 28 999 / 29 150 (**151 B**), dom base 22 334 / 22 400 (**66 B**), **K.8 guard 84 847 / 84 900 (53 B; ARCH K.8 ceiling 85 000)**, Angular 7 316 / 7 350 (34 B), `core/tree` 3 399 / 3 500, `dom/tree` 3 821 / 3 850, `core/csv` 1 866 / 2 000, `dom/print` 1 598 / 1 600, `core/state` 1 500 / 1 500, `dom/state` 1 174 / 1 200, `column-menu` 4 297 / 4 300, `dom/columns` 3 988 / 4 200. Real Angular example: ceiling 95 000, 94 609 at the close (ROADMAP « Phase 6 — close »), not measured since `clearFilters` / `resetState`. **Any base byte lands in K.8, which has 53 B before its hard ceiling's 153 B.**
20. **Text cost.** « text sort 100 000 fr (cold rank keys) » ≤ 171 ms (`perf/budgets.json`): grouping by a text column must not rank 100 000 values with the collator to find equal ones, or it misses the 150 ms alone. Equality by exact value (a `Map`), the collator over the **distinct** values only.
21. **Sehhaty.** ARCH §2.10 lists `admin-lab-facilities` as « a few hundred + sub-list, client, master/detail, Phase 6 » (l. 850), while §6 says Phase 7 grouping enables it (l. 1862, 1887); `docs/sehhaty-track.md` says nothing of it. `pharma/history`, `labo/history`: 15 k–150 k a year, server-paged or client, « regroupement éventuel » (l. 849). **What these screens group by, and whether they need grouping and details together (fact 1b) or grouping on a server (fact 16), is not known from the repo**: Q-SE.

## 2. Decisions to take (D1…D20; the owner's answers win)

- **D1 entries** (Q-B): all optional, a flat grid pays nothing. `@dzgrid/core/grouping` (pure: the grouped rows view, typed keys, aggregations, footers, totals; no DOM, no `Date`); `@dzgrid/dom/grouping` (the feature: hands the shape, paints the group column, group cells, footers, keys, `aria-*`, sentences, the API `setBy` / `by` / `expandAll` / `totals`) — **not `dom/groups`** (fact 17); `@dzgrid/dom/group-zone` (the « Nom × » band, over `dom/grouping`; the drag through `dom/columns` when present). Texts `locales/{en,fr,ar}-group` (zone, sentences, aggregate names); styles `@dzgrid/theme/grouping.css` (+ unlayered copy). Shared source: the tree's build (`core/src/tree/build.ts`) and the tree painter (`dom/src/tree/index.ts`) factored into internal modules both entries import (a grid with only one of them pays once).
- **D2 the grouped rows view.** (A ★) a **group structure on the tree's machinery**: a `groupStructure(snap, by)` sibling of `pathStructure` where rows are always leaves under their last group (fact 2a) and segments are typed (D3); then `withFillers` / `buckets` / flatten reused, the result a `TreeRows` plus `aggAt(i)`. Expansion, focus fallback, `aria-*`, keys, sticky parents, CSV lines come with it (facts 8, 9, 11). (B) a new model of its own (a group index per level, flattened separately): more bytes, a second hierarchy to keep right. (C) translate grouping into a `path` tree (`path(row) = values`): impossible as is (fact 2: rows claim nodes, untyped segments).
- **D3 keys of group rows.** One family with the tree's fillers, `g:` (they never share a grid, fact 1b), each segment `<column id>` + a type tag + the canonical value: `n` + the number's canonical text (`-0` = `0`), `s` + the text **as is** (no case or accent folding: « Alger » and « alger » are two groups; Q-G3), `d` + `YYYY-MM-DD`, `i` + epoch ms, `b` + `0|1`, `e` + the enum value, `∅` for null / blank / unreadable (one « (Vide) » group). Built with `groupKey` (length-prefixed: a host id can never pass for one). With the column id in the key, regrouping by another column never reopens a stale group (fact 4a). Footers: `f:` + the group's key; grand total: `t:top` / `t:bottom` (a key maker in `core/grouping`, or in `ids.ts` if the base must recognise it: 0–30 B). **Never in a `Problem`, the state, an event's detail or the address** (fact 4b; `rowExpanded` carries keys in memory only, as today).
- **D4 aggregation functions** (ARCH §3.13). `sum` (Neumaier compensated), `avg` (kept as the pair `(sum, count)`, so a parent merges its children without reading rows again), `min`, `max`, `count`, `first`, `last`, and custom `(values, ctx) => unknown` (pure, called per group with the group's leaf values, not merged). Per column: `ColumnDef.agg?: AggName | AggFn` (type only, 0 B) and/or `grouping({ aggs: { column: name } })`. Types: `sum` / `avg` on `number` only; `min` / `max` / `first` / `last` on number, `day` (compared as text `YYYY-MM-DD`, never a `Date`), `instant` (as epoch ms), text (collator order, for `min` / `max`); `count` on anything. A function that does not fit the type: `agg-type` warning (path `columns.<id>.agg`), the cell left empty. **Nulls**: skipped by every function except `count` (Q-A2: `count` = rows of the group ★, or non-empty values); a group with only nulls shows empty, never 0 for `sum`. **Precision**: the result is a JS number formatted by the column's own `numberFormat`; `avg` gets the column's format, no extra decimals; exact decimals stay out of v1 (ARCH). Values read **through the edit overlay** (the reader), so an edited cell counts as shown. Values read once per build from the column cache (`cache.keys`, `client.ts` env) where the codec's keys are numbers.
- **D5 where aggregates show.** (A ★) **in the group row's own cells**, under each aggregated column, written by the feature in `afterRows` as the tree writes a filler's label (fact 10; 0 B base; text through the column's codec and format, its alignment; no cell part there in this phase). (B) a base seam so group cells go through `#fillCell` with parts (+40–80 B dom base, which has 66 B). Footers: `footers: 'none' ★ | 'group' | 'grand' | 'both'` (ARCH `GroupingOptions`); a group footer is a row after the open group's last child, same aggregates, label « Total Nom »; while a group has a footer and is open, its own row keeps its aggregates (Q-A3: keep ★ or blank them). **Grand total** (Q-A1): (A ★) a footer row at the **end of the rows** (scrolls with them; also at the top with `grandTotal: 'top'`), never selected, never edited; plus `api.totals()` (aggregates of the whole filtered set, by column id) so an application can feed a sticky pinned row itself; (B) a **sticky** band at the bottom, reusing `pinned-rows/band.ts`' layout with non-`T` nodes (pinned-rows grows ~300–500 B, and a grouped grid then needs `pinnedRows` loaded); (C) the application only, through `totals()`.
- **D6 the group column.** (A ★) **the tree's way**: the group's label (the formatted value, then « (n) », the leaf count) goes into one existing column, the first visible one by default or `grouping({ column })`, with the indent and the chevron; data rows keep their own value there, indented. 0 column added, nothing in the column model, chooser or state. (B) an **automatic group column** added before the others (its own header « Groupe », width, sort): a synthetic column in the column model (core base bytes, the chooser, menus, `GridState` and `columns.set` all learn it), nicer for wide grids. (C) one auto column per level. The grouped columns themselves: see D13.
- **D7 sort.** Leaves sorted inside their group by the current sort (the tree's « one sort, then bucket », fact 2). Groups: (A ★) by their **value, ascending**, in the column's own order (numbers by number, days by day, text by the collator over distinct values, fact 20; « (Vide) » last), **reversed when the user sorts that column descending**, so a click on a grouped column's header orders its groups; (B) by first appearance in the sorted rows (what the tree's fillers do today); (C) also by an aggregate when the user sorts an aggregated column (ARCH `sortGroups: 'by-agg'`), groups then ordered by that aggregate at every level (Q-S: ★ in this phase or later).
- **D8 filter, search, pages.** Filters and the quick search test **leaf rows only**, before grouping (fact 5); a group with no matching leaf disappears; aggregates are over the **filtered** leaves (★; option: over all leaves, which no user can check on screen). Group labels and aggregates are not searched. No filter on aggregates (advanced filter, Phase 9). Counts: `counts.filtered` and the sentences count data rows (`dataCount`), not groups. Pages: (A ★) **grouping + browser pages refused** (`unsupported-combination`, as the tree: the groups are shown whole); (B) pages over displayed rows, groups included (a group cut in two over two pages).
- **D9 expansion.** The kernel's set, by group key (fact 8): kept across sort, filter, search, transactions and edits, since a group key is its values (a group that empties then comes back reopens as it was). `grouping({ expanded: 'none' | 'all' | depth })`, default **closed** ★ (Q-E1); `expandAll` / `collapseAll` and « to level n » through `rows.expandAll { depth }`; `*` opens siblings. Under a filter, the tree's « layer » rule (`tree-filter.md`): ★ **not** applied to groups — a filter does not open groups by itself (they hold matches by construction; opening all of them on each keystroke would flood the screen); option: open groups while a search is typed (Q-E2). A change of `by` keeps the set (keys carry column ids, D3: old keys simply match nothing; pruned at the next change). **Not in `GridState`** (Q-S1, and fact 4b: the keys hold row values).
- **D10 selecting a group row.** (A ★) **never selected** (as a tree's filler): a click focuses it, Space does nothing, no checkbox; Ctrl+A and the header box take the data rows shown, so leaves of closed groups are **not** taken (`tree-selection.md`, « what you see »). (B) a **tri-state checkbox** on group rows (`aria-checked="mixed"`): ticking selects the group's filtered leaves, shown or not (the `selection.tree: 'cascade'` noted in `tree-selection.md` « Later »; client only). Health data argument of Phase 4 Q2: ticking a group must not tick hundreds of patients unseen. Q-SEL.
- **D11 keyboard and accessibility.** The tree's keys in the group column (`tree-keys.md`): forward opens, back closes or goes to the parent, mirrored in RTL (exit criterion), `*`, Up / Down across levels, Home / End / PageUp / PageDown flat. On a group row, which has nothing to edit: Enter toggles it ★ (Q-K1; in the tree Enter keeps its flat meaning). Group rows: `aria-level` (1 = top groups; leaves at `by.length + 1`), `aria-posinset` / `aria-setsize` among sibling groups, `aria-expanded`; footers and the grand total: rows with no `aria-expanded`, the level of their group's children, a row header « Total {name} ». The grid's role `treegrid` while `by` is not empty, `grid` when it is. Sentences: the tree's « Nom expanded, n rows » / « collapsed » with the group's label; `zone.*` from the sheet. Pinned group rows while scrolling (`tree-sticky.md`): ★ on, as the tree (`sticky: 3`).
- **D12 the zone** (`group-drop-zone.md` part 2, already written; confirm its three « choices to confirm »): a `toolbar` above the header row inside the grid's root (`group({ zone: true })` or a separate `groupZone()` feature, Q-Z1), empty text « Glissez une colonne ici pour regrouper », chips « Nom × » in grouping order, logical (first at the start: the right in Arabic); keys of the sheet (arrows mirrored, Home / End, Delete / Backspace removes, Ctrl+Shift+arrows moves a chip); a header dropped on it through `dropTargets` (fact 12; `accept`: not already grouped, `groupable !== false`); a chip dragged inside the zone reorders (mouse and pen; no finger drag, as headers, Q-M3; Ctrl+Shift+arrows on a chip and the menu are the 2.5.7 no-drag ways); a chip dragged out does nothing. Only on the grid it belongs to (sheet 5). `ColumnDef.groupable?: false` (type only).
- **D13 the column menu and hiding grouped columns.** `columnMenu({ use: { grouping } })` adds « Regrouper par cette colonne » / « Ne plus regrouper par cette colonne » (the 2.5.7 no-drag path; grant on `column-menu`, fact 13). Grouped columns: (A ★) **stay visible** (the protocol's choice 1; the user hides them through the menu if they want, and the group column shows the value anyway); (B) `hideGrouped: true` hides them while grouped, through **a second folded set** in the column model (the base `shown` filter reads two sets: core base ~30–60 B, fact 14), never through `hidden`, so the state and the chooser never see it.
- **D14 edits.** A grouping column is a read column: (A ★) the shape tells the model the columns it reads (`RowShape.reads?(): string[]`, added to `touches`, `client.ts:356`; core base ~20–40 B): an edit of a grouping column marks the order **stale**, the row stays in its group until « reapply » (K.14, `edit-reapply.md`); then it moves, and an open group it lands in shows it. **Aggregates refresh at once** after an edit (they are what the user checks a bulk edit against): the model tells the shape that values changed (`RowShape.values?(changed)` from `setReader`, core base ~20–40 B), the shape recomputes the aggregates of the changed columns (mergeable ones: only the touched groups; others: the whole column) without moving any row. Group rows are never editable (fact 4). (B) aggregates wait for « reapply » too (one rule, but a total that lies after an edit).
- **D15 transactions and speed.** (A ★) **full regroup** on any data change, as the tree (fact 6), measured on A: target ≤ the build line (est. 40–80 ms for 100 000 rows, 2 levels) — a live feed of one row a second is fine, a ticker is not; an update that touches no grouping column re-aggregates only (no structure rebuild), as the tree's toggles skip the build. (B) incremental (insert / remove a leaf in its group, subtract / add for `sum` / `count` / `avg`, recompute `min` / `max` of the touched groups only): faster, much more code; done only if (A) misses its line (Q-T).
- **D16 server.** (A ★) **out of Phase 7**: `grouping()` on a server source gives `unsupported-combination` (`path: 'grouping'`) and the grid stays flat (fact 16: a page's totals presented as the whole's are wrong numbers on health and pharmacy data). Phase 8 brings server-side groups (`GroupRequest`, aggregates from the server, lazy groups over the tree-lazy seam). (B) allow it on a **client-paged** source only (`operations.page: 'client'`, all rows in the browser), refused on a server-paged one. (C) allow it everywhere with a visible « page only » warning.
- **D17 GridState.** A new optional part **`rowGroups: string[]`** (column ids, in order; not `groups`, fact 15), through a `StateEnv.rowGroups` adapter `{ get, set }` like the header groups; restore order: columns → groups → density → **rowGroups** → one `query.set` → page size → page; unknown ids `state-column`, a non-groupable column `state-field`; never expanded groups (D9). Written in the address by default (column ids are not row data). `core/state` +60–100 B (0 B margin today) and `dom/state` +20–40 B. Reset brings the definition's `by` back.
- **D18 CSV and print.** CSV: group lines already come with the label and the level column (fact 11); (A ★) **write the aggregates** in the group and footer lines (`core/csv` writes a group node's aggregate cells through the column's writer: +80–150 B, margin 134 B), `csv.groups: 'rows' ★ | 'none'` (`none`: data rows only, flat, for a spreadsheet's own pivot). `all` = every group open. Print: (A ★) print group rows (label indented, aggregates) and footers like data rows (`dom/print` +100–200 B, margin 2 B: grant); (B) data rows only (today's O9 rule extended), groups lost.
- **D19 Angular.** `[grouping]` stays through `[features]` (the wrapper adds nothing for the feature itself); added: an input `[groupBy]` (string[], two-way with `(groupByChanged)`) for NgRx-style screens, `DzgController.groupBy(by)` / `expandAll()` / `collapseAll()`, the zone through `features`. `rowGroups` rides in the existing `[state]` / `(stateChanged)`. Angular +80–150 B (34 B margin: grant).
- **D20 combinations.** Refused beside grouping, with `unsupported-combination` and the grid shown grouped without the other: tree (one shape, fact 1b), master/detail (the same; Q-SE asks whether `admin-lab-facilities` needs both), cell spans (as the tree), browser pages (D8), server sources (D16). Allowed: pinned rows (never grouped, `api.totals()` can feed them), auto row height (group rows take the row height), the edit layer (D14), range / fill / clipboard (they skip non-cell keys already), filters, quick search, column menu, chooser, state, print, CSV, motion (the tree's open / close animation, if `motion-gsap` is loaded).
