## Le thème

`@dzgrid/dom` injecte de lui-même le CSS de mise en page de la grille ; `@dzgrid/theme` la rend présentable (couleurs,
traits, en-tête, survol, sélection, focus, fenêtres surgissantes), en clair et en sombre, avec des contrastes vérifiés.
Chaque fonction qui a un aspect a sa propre feuille, chargée après `dzgrid.css` : `columns.css`, `menu.css`,
`grouping.css`, `pivot.css`, `edit.css`, `range.css`, `fill.css`, `dock.css`, `columns-panel.css`,
`filters-panel.css`, `find.css`, `search.css`, `print.css`, `row-drag.css`, `pinned-rows.css`, `row-numbers.css`,
`fresh-rows.css` ; `variables.css` pour les réglages de présentation (plus bas).

```ts
import '@dzgrid/theme/dzgrid.css';
import '@dzgrid/theme/menu.css';
import '@dzgrid/theme/contrast.css';   // plus de contraste quand le système le demande
```

- **Couche de cascade.** Chaque règle est dans la couche `dzgrid` : vos propres classes l’emportent sans
  `!important`. Quand vous rangez votre propre CSS en couches, nommez l’ordre une fois, en premier :
  `@layer theme, base, dzgrid, components, utilities;`. Avec une remise à zéro hors couche (le preflight de
  Tailwind 3, le Reboot de Bootstrap), chargez plutôt les copies `*.unlayered.css`.
- **Passerelles.** `tailwind.css` (Tailwind 4), `tailwind3.css`, `bootstrap.css` (5.3, suit `data-bs-theme`)
  rattachent les couleurs, la police et les coins de la grille à ceux de votre framework.
- **Thèmes vitrines.** `midnight.css` et `clinic.css`, chacun avec un jumeau clair et un sombre ;
  `data-dzg-skin="midnight"` sur un conteneur n’habille que cette zone.

## Couleurs et tailles

Les couleurs sont uniquement des variables CSS. La palette (partagée avec tzslot), chacune une paire `light-dark()`
sur `:root` : `--tz-bg`, `--tz-bg-raised`, `--tz-fg`, `--tz-fg-muted`, `--tz-border`, `--tz-accent`, `--tz-accent-fg`,
`--tz-danger`, `--tz-warning`, `--tz-success`. Ce que la grille en tire, à poser sur n’importe quel ancêtre de
`.dzg` : `--dzg-font`, `--dzg-radius`, `--dzg-cell-padding-inline`, `--dzg-header-bg`, `--dzg-row-hover-bg`,
`--dzg-row-selected-bg`, `--dzg-focus-ring`, `--dzg-line`, `--dzg-pill-radius`, `--dzg-header-size`,
`--dzg-select-bar`, `--dzg-flash`, `--dzg-flash-color` — chacune dans le tableau ci-dessous. L’accent propre à ce site
est le `--tz-accent` de la grille : passez le site en sombre et chaque démo suit.

```css
:root { --tz-accent: light-dark(#7c3aed, #c4b5fd); }
.dzg { --dzg-radius: 6px; --dzg-font: "Atkinson Hyperlegible", system-ui, sans-serif; }
.dzg-cell.is-late { color: var(--tz-danger); }
```

### Toutes les variables

Posez n’importe laquelle sur un ancêtre de `.dzg` (ou sur `.dzg`), ou depuis le code avec le réglage `theme`
ci-dessous. *Feuille* dit quelle feuille de style la lit : **base** = `dzgrid.css` (et la mise en page qu’injecte
`@dzgrid/dom`) ; **variables** = `@dzgrid/theme/variables.css`, chargée après `dzgrid.css` (`variables.unlayered.css`
après la copie hors couche) — elle ne change rien à elle seule ; la feuille d’une fonction est nommée. *Clé* est la clé
du réglage `theme`.

Les clés sont celles du tableau ; chacune est écrite sur la racine de la grille, si bien qu’elle l’emporte sur vos
feuilles de style pour cette grille seulement. Une valeur est une valeur CSS ou un nombre (`600`) ; une clé absente du
tableau ou une valeur avec `;`, `{`, `}`, `<`, `\`, `!` ou `url(` est signalée (`invalid-setting`, chemin
`settings.theme.<key>`) et laissée de côté. Le contraste reste à votre charge :
`npm run check:contrast -- --palette` vérifie un fichier de palette.

### Icônes

La grille dessine ses propres marques (caractères et formes, aucun fichier, dans la couleur du texte). Pour dessiner
les vôtres :

```ts
import { createGrid } from '@dzgrid/dom';
import { theming } from '@dzgrid/dom/theme';
import { FR } from '@dzgrid/dom/locales/fr';

type Hive = { id: string; name: string; frames: number };
const funnel = document.querySelector<SVGSVGElement>('#my-funnel')!;   // un <svg> déjà dans la page : copié

createGrid<Hive>(document.getElementById('hives')!, {
  rows: [{ id: 'h1', name: 'Ruche du verger', frames: 10 }],
  columns: [{ id: 'name', header: 'Ruche' }, { id: 'frames', header: 'Cadres', type: 'number' }],
  getRowId: (h) => h.id,
  messages: FR,
  icons: { sortAsc: '<svg viewBox="0 0 16 16"><path d="M8 3l5 8H3z"/></svg>', filter: funnel },
  features: [theming()],
});
```

Noms : `sortAsc`, `sortDesc`, `filter`, `filterActive` (celle d’une colonne filtrée ; sinon `filter` dans la couleur
d’accent — donnez-la pour garder une marque qui ne tienne pas qu’à la couleur), `menu`, `chevron` (arbres, détails,
groupes d’en-têtes : tournée et mise en miroir comme celle par défaut), `submenu`, `grip`. Une chaîne SVG ou un élément
(copié). Sa forme est dessinée dans la couleur et la taille de la marque (`--dzg-icon-size`), quel que soit son propre
remplissage. Refusé, avec la marque par défaut gardée et `invalid-setting` signalé : tout ce qui n’est pas un `<svg>`
fait de formes, groupes, dégradés, `use` et `title` ; un `<script>`, `<style>` ou `<foreignObject>` ; un attribut
`on…` ; un lien ou un `url()` qui sort de l’icône (seulement `#…`) ; plus de 20 000 caractères. Dessinée comme une
image `data:` : une CSP doit permettre `img-src data:`. Avec `injectStyles: false`, chargez aussi
`ICONS_CSS` de `@dzgrid/dom/theme`.

### Lignes alternées, traits, le bord figé

```css
.dzg {
  --dzg-row-odd-bg: color-mix(in srgb, var(--tz-accent) 6%, var(--tz-bg));     /* base */
  --dzg-pinned-shadow: 6px 0 6px -4px color-mix(in srgb, var(--tz-fg) 35%, transparent); /* base */
  --dzg-column-line: var(--dzg-line) solid var(--tz-border);                     /* variables.css */
  --dzg-frame: none;                                                             /* variables.css */
}
```

Le titre d’un en-tête suit l’`align` de sa colonne (les nombres à la fin) ; `headerAlign` sur une colonne le place
autrement.

**Clair et sombre** suivent le système ; `data-theme="light"` ou `data-theme="dark"` sur n’importe quel ancêtre en
impose un.

**La hauteur des lignes** vient du réglage `density` (`compact` 28 px, `comfortable` 32 px, le défaut, `spacious`
40 px) ou de `rowHeight` en pixels, qui l’emporte. Les lignes suivent le zoom du texte du lecteur. Le menu de colonne
peut proposer la densité à l’utilisateur (`columnMenu({ density: true })`), et l’[état](../state/) la garde.

**La hauteur de l’en-tête** : les lignes d’en-tête ont la hauteur d’une ligne, sauf si `headerHeight` (en pixels,
24 au moins, en direct) les rend plus hautes — `{ rowHeight: 40, headerHeight: 70 }`, Angular `[headerHeight]="70"`,
`<dz-grid header-height="70">`. Elle règle la ligne des en-têtes de colonnes et les lignes de groupes de colonnes
au-dessus (un en-tête de 70 px avec une ligne de groupe fait 140 px) ; la ligne de filtres garde la hauteur des
lignes. Elle suit le zoom du texte comme les lignes ; des titres verticaux font encore grandir la ligne quand ils en
ont besoin. La grille l’écrit sur sa racine en `--dzg-header-height` (en lecture seule, comme `--dzg-row-height`).

Depuis 1.10.0, les lignes de groupes ont leur propre hauteur : `headerHeight: { columns: 70, groups: 30 }` (`columns`
absent : la hauteur des lignes ; `groups` absent : celle des colonnes). La ligne de filtres a aussi la sienne :
`filters({ floating: true, rowHeight: 44 })`. Des titres sur plusieurs lignes (`headerWrap`, [colonnes](../columns/))
font grandir la ligne des en-têtes de colonnes ; la plus haute l’emporte.

**La hauteur de la grille vient de son conteneur**, jamais de ses lignes : donnez une hauteur à l’hôte (fixe, une part
de flex ou de grid, `100dvh` moins une barre) et la grille la remplit quel que soit son nombre de lignes (depuis
1.11.0) ; les lignes défilent à l’intérieur. Il n’y a pas de mode « aussi haute que ses lignes » — la page sauterait
chaque fois qu’un filtre change leur nombre.

**La colonne sous le pointeur** (1.10.0) : `columnHover()` de `@dzgrid/dom/column-hover` écrit `data-hover-col` sur la
racine et `data-col-hover` sur les cellules de cette colonne (souris et stylet seulement, jamais le clavier) ; la
teinte est à vous :


## Droite à gauche

Le sens d’écriture est pensé dès le départ : colonnes figées, défilement, touches fléchées (en arabe, → va vers le
début, qui est à droite), fenêtres surgissantes, retrait de l’arbre et thème le suivent tous. Tout dans DzGrid parle
de **début** et de **fin**, jamais de gauche et de droite : `pinned: 'start'`, `align: 'end'`, la zone `start` du
dock.

- `direction` : `'ltr'`, `'rtl'`, ou `'auto'` (le `dir` de l’ancêtre le plus proche).
- `numerals: 'locale'` affiche les chiffres propres à la langue (arabes orientaux pour `ar`) ; le défaut `'latn'`
  garde 0–9.
- Le tri et la recherche suivent la langue : formes de la hamza, voyelles brèves et tatweel, chiffres arabes
  orientaux.
- Votre propre CSS devrait aussi utiliser les propriétés logiques : `margin-inline-start`, `inset-inline-end`,
  `text-align: start`.
- Trois langues sont livrées : `EN`, `FR`, `AR` (`@dzgrid/dom/locales/*`), chaque fonction avec son propre lot de
  textes, règles de pluriel comprises. Une autre langue est un objet `GridMessages` à vous, avec les mêmes clés ;
  `checkMessages(messages)` lève une erreur qui nomme les clés manquantes.
