A tooltip on each cell, computed from the data.

## What it does

`tooltip(value, row, context)` returns the text, already translated, or null for none; `context` is the
grid's [`context`](../../settings/context/). The grid never guesses one from the cell's content. It shows when the
pointer rests on the cell (after the grid's [`tooltips`](../../settings/tooltips/) delay) and as soon as the keyboard
focus reaches it.

**In one line** (1.12.0): `tooltip: true` shows the cell's text as displayed; `tooltip: { when: 'truncated' }` only
while that text is cut; `tooltip: false` none, even under the grid's `tooltips: { cells: 'truncated' }`. Options
`{ text, when, delayMs, content }`: `text` left out means the cell's displayed text, `delayMs` is the column's own
hover delay, and `content(value, row, context)` the cell's own answer laid over them (words, options, or null for
none). A function may also return options instead of words.

The options may carry a look — `tone`, `placement`, `animation`, `shape`, `style`, `maxWidth`, or `html` — that
the grid's own tooltip does not draw: [DzTooltip](../../guides/tooltips-popovers/)'s bridge does,
`features: [dzTooltips({ … })]`. Without it the grid shows the words and tells once `missing-feature`.

## Example

```ts
import { createGrid } from '@dzgrid/dom';
import { EN } from '@dzgrid/dom/locales/en';

type Bee = { id: string; hive: string; honey: number };

createGrid<Bee>(document.getElementById('hives')!, {
  rows: [{ id: 'h1', hive: 'Clover hill', honey: 12.5 }],
  columns: [
    { id: 'hive', header: 'Hive', tooltip: (v) => (v ? `Hive ${v}` : null) },
    { id: 'honey', header: 'Honey', type: 'number', tooltip: { when: 'truncated' } },
  ],
  getRowId: (r) => r.id,
  messages: EN,
});
```
